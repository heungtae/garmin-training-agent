# Garmin Training Agent 통합 요구사항 명세서

- 문서 유형: 소프트웨어 요구사항 명세서(SRS)
- 버전: 1.1
- 작성일: 2026-11-15
- 상태: 설계 입력용 개정 초안 (개인화·적응형 훈련 기능 추가)
- 범위: 요구사항 및 검증 기준만 기술. 아키텍처, 모듈 구성, API 설계, 데이터베이스 설계, 파일 트리, 코드·라이브러리 선정은 포함하지 않음.

## 1. 목적 및 배경

본 제품은 개인 사용자의 Garmin 운동·회복 기록을 Linux 컴퓨터에서 주기적으로 수집해 GitHub 또는 Google Drive에 보관하고, ChatGPT가 저장된 데이터를 분석하도록 지원한다. 더 나아가 사용자는 ChatGPT 내 Garmin 훈련 관련 Plugin/Skill 워크플로에서 운동 목표를 등록하고, 과거 운동 데이터에 근거한 훈련 계획을 수립·검토·승인하여 Google Drive에 저장할 수 있어야 한다. Linux에 설치된 프로그램은 승인된 훈련 계획을 자동으로 확인하고, 선택된 외부 LLM의 평가 기능을 활용하며, Google Calendar에 훈련 일정을 제공해야 한다.

제품은 개인용 사용을 우선하며, ChatGPT와 Linux 설치 프로그램 간 직접 호출을 필수로 요구하지 않는다. ChatGPT↔저장소↔설치 프로그램 간 비동기 협업을 전제로 하되, 실제 연결 기능의 지원 여부는 선행 검증한다.

### 1.1 이번 개정의 범위

본 개정은 기존 요구사항을 유지하면서 **생활 일정 기반 훈련 배치, 장기 기억, 설명 가능한 변경, 다종목 훈련 관리, 목표 달성 전망 및 시나리오 비교, 컨디션/운동 피드백, 계획 품질 평가, 확장 가능한 훈련 전달 대상**을 추가한다. 추가 기능의 우선순위는 제품 차별화 효과와 구현 위험을 고려한 제안이며, 외부 서비스의 기능·계약·권한은 실제 검증을 전제로 한다.

| DEC-012 | 자동 생성·평가·계획 변경 **제안**과 사용자 **승인·적용**은 반드시 구별한다. |
| DEC-013 | 계획의 변경 근거·사용한 자료·불확실성을 사용자에게 설명할 수 있어야 한다. |
| DEC-014 | 운동 데이터, 사용자 진술, 추론·가설은 서로 다른 신뢰 수준으로 취급한다. |

| VAL-004 | Google Calendar 사용 계정의 OAuth 권한, 캘린더 생성·이벤트 쓰기 지원 | 연결·권한 실패가 계획 원본을 손상시켜서는 안 된다. |
| VAL-005 | Garmin Connect 캘린더/기기 직접 훈련 게시에 필요한 별도 공식 API 자격 | 권한 확보 전에는 자동 게시 가능 기능으로 안내하지 않는다. |
| VAL-006 | Google Calendar 일정의 조회 범위·수정 권한 및 사용자의 타 일정 접근에 대한 동의 | 훈련 일정 게시만 허용하는 환경에서는 생활 일정 충돌 분석 기능을 비활성화하고 이유를 알린다. |
| VAL-007 | Intervals.icu 등 제3자 운동 플랫폼의 현재 공개 API, Garmin 동기화 정책과 사용 조건 | 검증되지 않은 Garmin 시계 자동 전송을 보장하지 않는다. |
| VAL-008 | 훈련 성과 예측 및 다종목 부하 지표에 필요한 최소 데이터·모델의 검증 가능성 | 데이터가 부족하거나 검증되지 않으면 수치 예측을 내지 않고 정성적 평가로 제한한다. |

> 위 사항은 구현 가능하다고 가정해 확정하지 않는다. 실제 제품 기능 범위 및 사용 가능 플랫폼을 확인하는 선행 검증 항목이다.

## 3. 사용자 및 업무 시나리오

### 3.1 사용자 역할

- **최종 사용자**: 프로그램 설치, Garmin 및 저장소 연결, 운동 목표 등록, 계획 승인, 일정 확인, 데이터 및 연동 상태 확인.
- **ChatGPT 훈련 지원 기능**: 목표 입력 안내, 자료 해석, 계획 생성·수정안 제안, 사용자 승인 확인, 지원되는 저장 기능을 이용한 결과 기록.
- **설치형 자동 실행 프로그램**: 기록 수집, 데이터 게시, 계획 수신·상태 확인, 외부 LLM 평가 요청, 승인된 일정 게시, 실행 결과 기록.

### 3.2 주요 사용 시나리오

- UC-01: 사용자가 Linux PC에 설치하고 Garmin 인증, 저장소, 자동 실행 주기를 구성한다.
- UC-02: 새 운동을 마친 후 정기 실행에서 해당 기록과 회복 데이터를 자동 수집한다.
- UC-03: ChatGPT 웹 또는 모바일에서 최근 운동·장기 추세를 질의한다.
- UC-04: ChatGPT에서 목표 종목, 날짜, 목표 기록, 운동 가능 요일, 제한사항을 대화로 등록한다.
- UC-05: ChatGPT가 Garmin 기록을 참고해 훈련 계획을 제안하고, 사용자의 수정·승인을 거쳐 Google Drive에 저장한다.
- UC-06: 설치형 프로그램이 승인된 계획을 확인하고 Google Calendar에 일정별로 게시한다.
- UC-07: 실제 운동 완료 후 계획 대비 실적을 분석하고 필요하면 수정안을 제시한다.
- UC-08: Garmin/Drive/GitHub/LLM/Calendar 중 일부가 일시 실패해도 나머지 데이터가 보존되고 이후 재처리된다.
- UC-09: 사용자가 예정된 업무·여행 등으로 특정 훈련을 할 수 없을 때, Agent가 가능한 일정과 회복 간격을 검토해 대체 일정을 제안한다.
- UC-10: 사용자가 운동 전 컨디션과 운동 후 체감 난이도를 기록하면 이후 계획 평가에 반영된다.
- UC-11: Agent는 과거 계획 이행률과 명시적 선호를 반영하되, 추정된 습관을 사용자에게 확인·수정받는다.
- UC-12: 사용자가 훈련 횟수·기간·목표를 바꾸는 가상 시나리오를 비교하고 불확실성을 확인한다.
- UC-13: 러닝·수영 등 여러 종목을 병행할 때 전체 일정과 회복 부담을 함께 검토한다.
- UC-14: 사용자는 훈련 변경의 이유를 확인하고 승인·거절하거나 다른 대안을 요청한다.

## 6. 상태 및 업무 규칙

1. 목표는 사용자에게 제시된 내용과 승인 여부가 구분되어야 한다.
2. 훈련 계획은 최소한 **초안 / 승인 / 게시 / 개정 또는 대체 / 취소** 상태가 구분되어야 한다.
3. 계획의 승인과 Google Drive 저장 성공, Rust 프로그램 수신, Google Calendar 게시 성공은 서로 다른 상태다.
4. 사용자가 승인하지 않은 초안은 캘린더 게시 대상으로 간주하지 않는다.
5. 동일한 계획 버전과 동일한 세션은 반복 처리되어도 중복 일정이 생기지 않아야 한다.
6. 계획 변경으로 이미 완료된 실제 운동 기록을 수정하지 않는다.
7. 외부 LLM의 제안은 사용자 승인 전까지 **제안** 상태로 취급한다.
8. Garmin 데이터의 미수집·누락은 사용자가 운동하지 않았다는 의미로 간주하지 않는다.
9. 목표의 위험성·실현 가능성·회복 상태 판단은 근거와 불확실성을 함께 제시한다.
10. 사용자 동의 없이 GPS 원본, 인증 정보 또는 필요 이상의 건강 데이터를 ChatGPT·LLM·공유 저장소에 전달하지 않는다.
11. 생활 일정의 충돌 여부 확인과 일정 변경 적용은 별개 단계이며, 변경은 명시적 승인을 거친다.
12. 명시적으로 입력된 선호와 추론된 습관을 구별하고, 추론된 습관은 사용자 확인 전에 확정하지 않는다.
13. 훈련 계획의 이행률은 데이터 미수집·휴식·운동 누락을 구별해 계산한다.
14. 가상 시뮬레이션은 실제 계획·캘린더와 혼동되지 않으며, 예측 수치는 근거와 검증 수준을 함께 표시한다.
15. 훈련 변경의 승인·거절·복구 이력이 남아야 하며, 이미 완료된 실제 운동 기록을 소급 변경하지 않는다.

## 8. 초기 릴리스 범위 및 제외 사항

### 8.1 P0 초기 필수 범위

- Rust 기반 Linux 설치형 자동 수집·동기화 프로그램.
- 설치 시 스케줄 등록·설정 및 운영 상태 확인.
- Garmin Personal API 운동 데이터 조회·정규화·보관.
- GitHub / Google Drive 연결 및 독립적 동기화.
- ChatGPT 분석에 필요한 최근·기간별 요약과 구조화 데이터 제공.
- ChatGPT Plugin/Skill 기반 목표 등록→계획 생성→검토→승인→Drive 저장 워크플로.
- 승인 계획을 설치형 프로그램이 주기적으로 확인·검증.
- 등록 가능한 외부 LLM을 이용한 훈련 계획 평가.
- Google Calendar 일정 게시 및 변경·실패 처리.

### 8.2 차별화 기능의 후속 범위

- **P1 우선 후보:** 생활 일정 충돌 탐지·재배치 제안, 사용자 선호·장기 코칭 이력, 변경 근거 설명, 다종목 분석, 운동 전후 피드백, 목표 시나리오 비교, 계획 품질 평가.
- **P2 확장 후보:** 검증된 정량 기록 예측, 고도화된 종목 간 부하 추정, 일정 파일 내보내기, 제3자 훈련 플랫폼·Garmin 시계 전달, 이중 모델 비교 평가.
- P1/P2 기능은 초기 핵심 수집·저장·계획 승인·Calendar 게시 흐름의 완료 조건을 임의로 변경하지 않는다. 우선순위 조정은 설계 착수 시 합의한다.

### 8.3 초기 범위에서 제외하거나 조건부인 항목

- Garmin Connect 캘린더/시계로의 훈련 계획 자동 게시(공식 권한 확보 전 제외).
- ChatGPT가 로컬 Linux 프로그램을 직접 호출하는 기능(요구하지 않음).
- 상시 실행 클라우드 서버 또는 별도 Garmin MCP 서버 구축(필수 아님).
- 유료·상용 다중 사용자 플랫폼 운영, 과금, 중앙 계정 관리.
- 별도 모바일 네이티브 애플리케이션 개발.
- Google Drive/ChatGPT 연결에서 실제 지원되지 않는 자동 쓰기를 확정 기능으로 간주하는 것.

## 10. 최종 완료 기준

본 제품의 초기 요구사항이 충족되었다고 판단하려면, Linux 사용자 PC에 프로그램을 설치하여 Garmin 운동 기록이 지정 주기로 수집되고, 선택한 GitHub/Google Drive에 분석 가능한 데이터가 저장되어야 한다. 사용자는 ChatGPT에서 별도 Linux 프로그램 호출 없이 목표를 대화로 등록하고 훈련 계획을 검토·승인해 Google Drive에 보관할 수 있어야 한다(실제 연결 환경의 쓰기 기능 확인 필요). 설치형 프로그램은 승인된 계획을 중복 없이 확인하고, 등록된 외부 LLM의 평가 기능과 Google Calendar 일정 게시 기능을 제공해야 한다. 일부 외부 서비스에 문제가 발생해도 기존 운동 기록·승인된 계획이 손실되지 않아야 하며, 사용자에게 해당 단계의 상태와 오류가 정확하게 표시되어야 한다.
