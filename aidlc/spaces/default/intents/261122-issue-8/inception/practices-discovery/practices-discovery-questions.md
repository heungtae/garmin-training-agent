# 개발 관행 확인

## Q1. 통합 방식

개별 PR을 어느 브랜치로 통합하고 어떤 병합 방식을 사용할까요?

A. `main`으로 PR을 열고 스쿼시 병합을 사용합니다.
B. `main`으로 PR을 열고 병합 방식을 PR 검토 시 정합니다.
X. Other (please specify)

[Answer]: A

## Q2. 첫 종단 간 검증

전체 스키마를 옮기기 전에 대표 스키마 하나의 로딩부터 검증까지 연결되는 작은 예제를 먼저 확인할까요?

A. 대표 스키마로 검증 흐름을 먼저 확인합니다.
B. 스키마와 레지스트리를 구성하면서 검증 흐름을 함께 확인합니다.
X. Other (please specify)

[Answer]: B

## Q3. 테스트 순서

합성 데이터 기반의 정상·오류·경계 테스트를 어떤 순서로 작성할까요?

A. 검증할 항목을 정의하고, 각 구현 단위 뒤에 해당 테스트를 작성하고 실행합니다.
B. 각 검증 항목의 실패 테스트를 먼저 작성한 뒤 그 테스트를 통과하도록 구현합니다.
X. Other (please specify)

[Answer]: B

## Q4. 배포 관행

이번 이슈의 산출물은 개별 PR입니다. 이 PR에 향후 배포 관행을 어떻게 기록할까요?

A. 이번 작업에서 배포 관행 결정은 보류합니다.
B. 향후 서비스는 병합 후 스테이징에 배포하고, 운영에는 별도 사람 승인을 적용한다는 기본안을 기록합니다.
X. Other (please specify)

[Answer]: B

## Q5. 코드 스타일

스키마와 독립 검증 코드의 스타일을 어떻게 맞출까요?

A. 승인된 스키마 표현과 저장소 설정을 따르고 검증 코드는 선택된 언어의 기본 포매터와 관례를 따릅니다.
B. 별도 포매터와 스타일 규칙을 지정합니다. 적용할 규칙을 함께 적어 주세요.
X. Other (please specify)

[Answer]: A
