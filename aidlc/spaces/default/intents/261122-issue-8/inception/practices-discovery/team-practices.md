# 개발 관행

이슈 #8의 승인된 인터뷰 답변을 반영했습니다.

## Way of Working

- **Integration branch**: main
- `feat/issue-8`에서 작업하고 개별 PR을 `main`에 스쿼시 병합합니다.
- PR에 검증 결과와 독립 리뷰 근거를 연결하고, 이슈는 병합 전까지 열린 상태로 유지합니다.

## Walking Skeleton

- 이슈 #8에서는 U1 스키마와 레지스트리를 구성하면서 로컬 등록, 참조 해석, 정상·오류 검증 흐름을 함께 확인합니다.

## Testing Posture

- **Methodology**: tdd
- **Methodology evidence**: Q3의 B를 선택했습니다.
- **Ordering**: 각 검증 항목의 실패 테스트를 먼저 작성한 뒤 그 테스트를 통과하도록 구현합니다.
- 승인 기준의 스키마 12개에 대한 메타스키마 검사, 로컬 참조 검사, 정상·오류·경계의 합성 사례 검증을 포함합니다. 재시도·동시성 조건 중 U1에서 확인 가능한 범위와 미실행 범위를 기록합니다.
- U1 자체 검증은 U2, U3, SDK 또는 DB 설치를 요구하지 않습니다. 실행 명령과 결과를 개별 PR에 기록합니다.

## Deployment

- 향후 서비스는 병합 후 스테이징에 배포하고, 운영 배포에는 별도 사람 승인을 받습니다.
- 이슈 #8의 산출물은 로컬 검증과 독립 리뷰 근거를 담은 개별 PR입니다.

## Code Style

- 승인된 스키마 표현과 저장소 설정을 따릅니다. 검증 코드는 선택된 언어의 기본 포매터와 관례를 따릅니다.
- 사용자 문서는 한국어로 작성하고 코드 식별자는 영어로 작성합니다. JSON Schema의 식별자와 참조는 승인 설계에 따릅니다.
