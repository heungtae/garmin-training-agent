## 이어받는 결정

- Ubuntu 24.04 이상·Rust 설치형·한 사용자/한 PC·CLI 운영. 수집/동기화 1시간과 계획 확인 15분을 독립 설정하고 로그아웃 중 실행을 검증할 대상으로 둔다.
- 로컬 우선 보존, 대상별 독립 게시, 중복/중단 재개·응답 유실 대조·사용자 수정 충돌 보류를 유지한다.
- Drive의 고정 버전 JSON, 전체 내용/정책 digest, 독립 승인 검증 및 미해소 시 관련 자동 게시/변경/취소 보류를 유지한다.
- 평가 결과는 미승인 조정안이며, 평가 호출 실패 예외는 기존 승인·형식·안전 검증을 통과한 변경 없는 정확한 버전에만 적용한다.
- 서비스별 공유·withheld·모든 실제 분석 경로 허용 집합 동일성·Detail 완전성 등 C01~C08의 최신 규범을 따른다.
- 원격 OpenAI API 초기 대상, Ollama 제외, 로컬/사설 대체 제공자 미정. 실제 Garmin·승인 신뢰·정책 최신성·클라이언트/외부 권한·모델/한도/비용의 차단을 유지한다.
- Calendar의 시간대·기본 시각·세션 시각 우선·기본 알림·미래 세션 변경/취소·타 일정/실제 운동 보존은 이미 결정됐다. 아래 질문은 아직 게시되지 않은 과거 시각 세션을 처음 생성할지에만 해당한다.

## Q1. 게시 시각이 지난 미게시 세션을 어떻게 처리할까요?

예: PC가 꺼져 어제 오전 세션을 게시하지 못했고 오늘 프로그램이 재개했다. 승인 계획 원본과 실제 운동 기록은 보존하며, 현재 시각을 신뢰할 수 없는 경우에는 보류한다.

A. 시작 시각이 지난 미게시 세션은 신규 생성하지 않고 건너뛴 사유와 상태를 남긴다. 미래 세션만 신규 게시하며 오늘 이후 시각으로 자동 이동하지 않는다. 초기 고정 정책으로 권장한다.
B. 승인 계획에 포함된 과거 시각 세션도 원래 날짜·시각으로 신규 생성한다. 현재 승인/안전/공유/권한·중복 검증은 동일하게 적용하고 오늘 이후 시각으로 이동하지 않는다.
X. Other (please specify)

[Answer]: A. 시작 시각이 지난 미게시 세션은 신규 등록하지 않고 상태와 사유를 남긴다. 미래 세션만 신규 게시하며 원래 계획과 실제 운동 기록을 보존하고 시각을 자동 이동하지 않는다.

## 미확정 범위 구분

기존 일정의 미래 변경/취소 범위·완료 실제 운동 불변·사용자 수정 충돌 보류는 Q1로 변경하지 않는다. 게시 기간 설정 기능(CAL-009, P1)을 초기 범위로 추가하지 않고 선택한 동작을 초기 고정 정책으로 설계한다. 구체 시간 제한·백오프·하드웨어·DB·비밀 보호·예약 실행 수단은 NFR 설계에서 선정하며, 실제 외부 계약/신뢰를 모의 입력으로 해소하지 않는다.

## 답변 분석과 경계 조건

- Q1은 신규 Calendar 생성 여부의 정책이다. 실제로 아직 생성되지 않은 세션의 해석된 시작 순간이 신뢰된 현재 시각보다 미래일 때만 신규 생성 후보로 삼는다. 이미 시작한 세션은 건너뛰며 현재 시각/시간대 해석을 신뢰할 수 없으면 보류한다.
- 이전 요청의 응답이 유실돼 원격 반영 여부가 불명확한 세션은 단순 미게시로 간주하지 않는다. 기존 의도·고정 이벤트 ID·버전/내용으로 먼저 조회·대조하고, 실제 미생성이 확인된 경우에만 Q1의 신규 생성 정책을 적용한다. 이미 생성된 일정은 과거가 됐다는 이유로 삭제하지 않는다.
- 건너뛴 사유와 처리 범위를 게시 성공과 구분해 남긴다. 원 계획의 날짜/시각·승인 내용·실제 운동 기록을 보존하고 자동으로 오늘 이후에 재배치하지 않는다. 기존 미래 일정 변경/취소·충돌·부분 실패 규칙도 유지한다.
- 다른 적용 경계는 승인된 요구사항·공통 계약에서 이어받는다. 두 예약 작업의 중복/재개, 인증/권한/디스크/네트워크 실패, 원천 수정/미완료 수집, 저장소별 성공과 충돌, 부분/구버전/불신 입력, 늦은 평가 결과와 미확인 외부 효과를 소유 컴포넌트별로 정의한다.
- 사용자 판단이 필요한 추가 모호성은 없다. 실제 외부 계약/신뢰·안전 근거·정밀도·한도·비용·환경 적격성의 기존 미해소 조건을 임의 확정하지 않고 관련 기능의 보류 조건으로 설계한다.

## Consolidated Summary Confirmation

- U2의 7개 컴포넌트·25개 원 소유 엔티티·배정 기능 요구사항 66개를 데이터 모델·업무 규칙·상태 전이·흐름과 추적성으로 구체화한다. U3 작성 엔티티나 U1 명세 소유권은 가져오지 않는다.
- CLI 설정·예약/즉시 실행·중복 제어·로그아웃 실행·복귀 후 재개를 설계한다. 수집/동기화 1시간과 계획 확인 15분을 독립 설정한다. 물리 DB·예약 실행 수단·비밀 보호·구체 한도는 NFR 설계에서 선정한다.
- Garmin의 확인된 원천 자료를 로컬에 먼저 확정하고, 원천 ID/개정·단위·시각·누락을 보존한다. GitHub/Drive는 각각 성공·실패·충돌·미확인 상태를 관리하며 정상 0건과 수집/접근 실패를 구별한다.
- C01~C08의 최신 공유·전체 내용 digest·고정 버전·withheld·상세 분할/집계/완전성 규칙을 적용한다. 모든 실제 분석 경로의 허용 집합이 다르면 자동 교집합 생성 없이 신규 전송을 보류한다.
- Drive 작성본을 불신 입력으로 수신하고 정확한 사용자·버전/내용·행위·현재 승인/철회·형식·안전을 독립 검증한다. LLM 결과는 제안이며 최종 게시 적격성은 PlanAdmission이 판단한다. 평가 호출 실패 예외는 기존 검증을 통과한 변경 없는 정확한 버전에만 적용한다.
- Calendar 신규 생성은 미래 세션만 대상으로 한다. 이미 시작한 미게시 세션은 건너뛴 사유를 남기고 원 계획·실제 운동을 보존하며 시각을 자동 이동하지 않는다. 응답 유실은 먼저 원격 반영 여부를 대조하며 기존 일정의 미래 변경/취소·사용자 수정 충돌·부분 실패는 기존 규칙대로 처리한다.
- 원격 OpenAI API 초기 대상·Ollama 제외·로컬/사설 대체 제공자 미정을 유지한다. Garmin 상세 계약·실제 승인/정책 최신성·ChatGPT/외부 권한·안전·모델/처리 위치/자원/비용 적격성이 미해소이면 해당 기능을 활성화하지 않는다.
- 확인 후 entities.md·rules.md·functional-spec.md·traceability.json을 작성할 입력으로 사용한다. 이번 작업은 기능·비기능 설계까지이며 제품 코드·설치·실제 외부 호출/인수는 수행하지 않는다.
