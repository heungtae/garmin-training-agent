## U2-P01 — 짧은 로컬 조회와 고정 입력 분석

대응: NFR8.1·NFR8.2. 소유: OperationControl(조회), AnalysisPublication(분석). 규칙: BR1.5·BR1.8·BR4.3·BR4.8.

상태/설정 조회는 일반 사용자 프로세스 시작에서 종료까지를 경계로 한다. 로컬 확정 개정과 소유자별 결과를 짧은 읽기 트랜잭션으로 읽고 한국어 결과를 만든다. 외부 인증 시험·네트워크·Schema 전체 재컴파일·대량 분석을 조회의 숨은 선행 작업으로 두지 않는다. DB busy도 [U2-R01](reliability-design.md#u2-r01)의 제한을 적용하며, 읽을 수 없으면 기존 성공을 꾸미지 않고 안전한 실패/조치를 반환한다.

분석은 시작 시 원천 활동의 정확한 개정 집합·기준시각·기간/시간대·tzdb·명세/계산 프로필을 고정한다. 활동을 기간/종목별로 순차 읽고 유일 ID 집합과 정확 합계를 관리한다. 기간·원천 개정에 대한 조회 인덱스와 짧은 읽기 묶음을 사용하되 구현 전 실행 계획/최대 RSS로 타당성을 확인한다. 분석 중 긴 쓰기 잠금을 잡지 않으며 입력이 바뀌면 혼합하지 않고 고정 개정으로 끝내거나 새 재계산 필요를 표시한다. 산출물 확정은 [U2-R02](reliability-design.md#u2-r02), 수치/시간은 [U2-R06](reliability-design.md#u2-r06)을 따른다. 속도를 맞추려고 반복 소수·누락 지표를 임의 반올림/0으로 바꾸지 않는다.

검증 설계: U2-S02·U2-S05(조회), U2-S14·U2-S16(분석)과 빈 입력·동시 원천 수정·DB busy/확정 실패를 독립 대역으로 비교한다. 합성 10,000활동에서 조회 p95≤2초, 분석 시작~로컬 확정 p95≤60초와 내용 정합이 동시에 필요하다. 계측 절차는 U2-P04다. 실제 구현/성능은 미검증이다.

## U2-P02 — 실행 deadline과 강제 종료 경계

대응: NFR8.5·NFR8.6. 소유: OperationControl(실행 예산), 각 요청 소유자(요청/자식), PlanEvaluation(LLM). 규칙: BR1.6·BR2.8·BR8.6.

실행 시작 단조 시각을 고정하고 총 600초에 실행권 대기·DB 대기·백오프·파싱·CPU·네트워크·정리·자식 종료를 모두 포함한다. 570초에 새 작업을 중단하고 남은 30초를 상태 확정과 종료에 남긴다. 그 이전에도 작업이 정리 여유를 침범하면 시작하지 않는다. 일반 요청 전체는 연결부터 본문 끝까지 min(30초, 정리 여유를 뺀 남은 시간), LLM은 min(120초, 같은 남은 시간), 연결은 min(10초, 해당 요청 deadline)이다. 하위 프로세스는 min(60초, 정리 여유를 뺀 남은 시간), 목적별 실행권 대기는 최대5초이며 전체 시간을 늘리지 않는다. 단조 시계/영속 대기 시각 대응은 [U2-R04](reliability-design.md#u2-r04)의 단일 정의를 사용한다.

HTTP 후보 Tokio1.54.1·reqwest0.13.5는 연결/본문 취소와 deadline 전파를 담당한다. 네트워크 timeout은 원격 취소나 미과금 증거가 아니며 원 소유자가 미확인 의도/예약을 보존한다. 비양보 CPU 연산은 Tokio timeout만으로 중단을 보장할 수 없으므로 파싱·Schema·JCS·계산의 작업 경계와 시간 검사를 둔다. 양보/취소를 입증할 수 없는 경계는 비밀을 전달하지 않는 제한된 하위 프로세스로 분리하고 실행 전체 프로세스 그룹 종료에 포함한다. CPU 작업 취소 뒤 미확정 파일/분석은 성공 참조로 게시하지 않는다.

OS 보조 종료는 [U2-L02](logical-components.md#u2-l02)의 Type=oneshot·TimeoutStartSec=595초·TimeoutStopSec=5초·KillMode=control-group을 사용한다. RuntimeMaxSec를 oneshot 상한으로 쓰지 않는다. 긴 ExecStop나 자동 재시작으로 600초를 연장하지 않는다. 정리 지연/강제 종료 시 외부 상태는 [U2-R03](reliability-design.md#u2-r03)으로 대조한다.

검증 설계: U2-S04·U2-S47·U2-S62에 느린 연결/헤더/본문, 양보 없는 CPU, 종료 무시 자식, cutoff 직전 요청, 잠금 충돌을 주입한다. 실제 프로세스 트리의 종료 완료까지≤600초·전송≤100회·미완료 보존을 확인해야 한다. OS kill 지연과 라이브러리 취소/CPU 상한은 아직 측정하지 않았다.

## U2-P03 — 유한 캐시와 자원 할당

대응: NFR8.3·NFR8.8. 소유: AnalysisPublication(분석 재사용), 각 검사 소비자(검사기), OperationControl(공통 자원). 규칙: BR1.6·BR4.4·BR4.8·BR10.4.

분석 재사용 키는 원천 개정 집합 digest·고정 명세/계산 프로필·전체 정책 digest·기간·시간대/tzdb·구현 빌드다. 현재 실행에서 한 번에 한 분석 묶음만 유지하고 실행 종료 시 메모리 캐시를 비운다. 키가 바뀌거나 자원 부족이면 재계산/보류하며 오래된 성공을 최신 결과로 제시하지 않는다. 영속 AnalysisSnapshot은 원본 불변 산출물이며 캐시 eviction으로 삭제하지 않는다.

Schema 캐시는 설치본에 고정한 registry 1.0.0의 Common+C01~C08 9개와 U2 평가용 LLM_REQUEST/LLM_RESPONSE/EVALUATION 3개, 총12개 root 스키마 범위로 제한한다. manifest digest/검사기 빌드가 바뀌면 모두 재생성하고, 등록되지 않은 스키마는 추가 캐시하지 않는다. 기본 패턴 가이드의 무한 TTL/원격 캐시는 적용하지 않는다. 권한·원 정책 현재성·철회·승인/안전 판정은 캐시된 통과로 재사용하지 않고 [U2-SEC03](security-design.md#u2-sec03)에서 요청 직전 다시 검사한다.

HTTP client는 프로필별 TLS/endpoint 설정으로 재사용하되 목적별 전송1개, CPU 하위1개·ID 대기32개와 전체 바이트 예산은 [U2-C01](scalability-design.md#u2-c01)을 따른다. 더 큰 캐시/연결 풀·별도 캐시 서버를 추가하지 않는다. 합산 RSS 한도를 넘거나 입증할 수 없으면 정상 처리로 판정하지 않는다.

검증 설계: 같은 키의 재사용/원천 개정 및 정책 digest·tzdb·빌드 변경/빈 캐시·한도 초과를 비교한다. 캐시가 현재성 검사 호출을 생략하면 실패다. 캐시 유무 성능·라이브러리 할당량은 미검증이다.

## U2-P04 — 시간·메모리·예약 측정 계획

대응: NFR8.1~NFR8.4·NFR11.1. 소유: OperationControl 및 후속 U2 개발/품질 담당.

기준은 Ubuntu24.04·CPU2코어·RAM4GiB·SSD·합성10,000활동/300세션이다. 최소 지원 사양이나 공급자 용량을 의미하지 않는다. CLI는 프로세스 시작~종료, 분석은 고정 입력 재계산 시작~로컬 완전본 확정으로 측정하며 외부 수집/게시/LLM은 분석 시간에서 제외 사실을 기록한다. 로컬/사설 추론 서버는 별도 적격 프로필로 제외 여부와 자원을 명시한다.

| 검사 | 고정 방법 | 판정과 증거 |
|---|---|---|
| 준비/지연 | 준비5회 뒤 측정20회, 단조 시계; 오름차순19번째 p95 | 조회≤2초/분석≤60초, 정상 기대 실패0건; 실패/timeout도 보고 |
| 첫 실행 | 빈 캐시 별도5회 모두 보고 | 준비 측정에 합치지 않고 새 시간 합격 기준을 만들지 않음 |
| 예약 | 무부하/기준부하/로그아웃 각5회; 예정~시작 기록 | 전원 켜짐·비절전·실행 조건/실행권 가능 시 각≤60초; 중복 억제는 시작 성공 아님 |
| 메모리 | 준비·측정·첫 실행·두 목적 중첩 전 구간, CLI/관련 자식 포함 실제 RSS 합산 | ≤1GiB; 100ms 표본과 종료 ru_maxrss 등 고수위·OS OOM 사건/프로세스 소멸 시각 병기 |
| 관측 한계 | 프로세스 트리 누락/표본 간 피크·동기화 공백·고수위의 시간 불일치 확인 | 개별 고수위 합은 동시 RSS와 다르므로 별도 표기; 피크 준수 입증 불가면 미검증 |

관리 서비스 공통 slice MemoryMax=1GiB는 최후 보호다. cgroup 메모리는 RSS와 다르며 CLI가 slice 밖이면 측정에서 빠뜨리지 않는다. OOM 종료·자식 누락·상한 초과는 합격이 아니다. 실제 합산 계측 도구/고수위 읽기·샘플러 오버헤드·OS 종료 상한은 후속 통제 실행으로 적격화해야 한다.

각 기록에는 환경·입력/설정/명세 digest·Cargo.lock/엔진/tzdb/빌드·캐시 상태·관측 경계/누락·기대/실제·실패 수를 남긴다. 건강 원문/비밀 대신 [U2-O01](observability-design.md#u2-o01)의 허용 필드를 사용한다. 현재 수행 범위는 문서 정합 검사이며 위 제품 시험 전부 미실행이다.
