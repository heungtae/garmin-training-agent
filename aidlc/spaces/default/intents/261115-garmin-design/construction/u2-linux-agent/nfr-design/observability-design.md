## U2-O01 — 허용 필드 로컬 기록과 한국어 CLI

대응: NFR7.1·NFR10.1·NFR1.1. 소유: 각 결과 소유자(사실), OperationControl(CLI/집계). 규칙: BR1.8·BR2.8·BR3.9·BR6.8·BR7.5·BR7.6·BR9.4.

컴포넌트는 성공/실패/미확인 사실을 자기 엔티티의 확정 기록으로 남기고 OperationControl에 불변 결과 참조를 돌려준다. 기존 DB 결과/시도 계보를 운영 원본으로 삼으며 별도 건강 원문 로그를 만들지 않는다. 보호된 로컬 JSON Lines 진단은 다음 허용 필드만 구조화 직렬화하고 줄바꿈/제어문자를 안전하게 이스케이프한다. journald에는 안전한 서비스 시작/종료/고정 상태만 전달한다. 로그를 먼저 저장한 뒤 마스킹하는 경로는 없다.

| 허용 범위 | 내용/판정 |
|---|---|
| 연결 식별 | 불투명 실행/작업 참조·목적·소유 컴포넌트·단계·대상 별칭·활동 또는 계획/버전/전체digest·세션·원 의도/시도·상위 작업 참조 |
| 상태와 시각 | 예정/실제 시작·종료·지연 사유·마지막/다음 실행(null 포함), 현재 결과와 별도 마지막 확인 성공, sourceCollectedAt/generatedAt/lastSuccess의 구분 |
| 수량/예산 | 처리/실패/pending 건수·cursor 존재/안전한 참조·실제 전송/시도 수·예약/남은 예산·미확인 비용 여부·nextAllowedAt·timeout/중복 억제·지연/RSS 요약 |
| 오류/조치 | Common.Error의 고정 code·검증된 fieldPath·workRef·고정 한국어 suggestedAction·재시도 가능/사용자 조치/재대조 필요 |
| 금지 | 요청/응답 원문·건강 수치/자유 서술·개인식별자·인증 헤더/비밀값/보호 보관 참조·원격 오류 원문·합성 음성 표식 echo |

불투명 참조도 허용 범위 밖 외부 전달의 근거가 되지 않는다. 필드 경로는 스키마/내부 고정 경로에서 만들며 사용자 임의 문자열을 그대로 넣지 않는다. 대상 별칭/식별자에 부적절한 내용이 섞인 경우 로그용 안전 참조로 연결하되 실제 도메인 ID는 저장 원본에서 보존한다. 로컬 조회는 [U2-P01](performance-design.md#u2-p01)처럼 네트워크 없이 읽는다.

CLI는 현재 데이터/동기화/인증·권한/LLM/Calendar 오류·대상·마지막 성공·재시도 가능 여부·다음 조치를 한국어 텍스트와 종료 결과로 구별한다. 최초/중단은 null과 이유를 보이고 색상만으로 상태를 구분하지 않는다. 늦은 성공 응답이 현재 오류/최신 상태를 덮지 않는다. 저장 실패로 기록을 확정할 수 없으면 안전한 최소 오류와 미확정 사실을 알리며 성공을 만들지 않는다. 종료/오류 범주의 숫자 매핑은 코드 생성 시 이 의미를 보존해 고정한다.

검증 설계: U2-S02·U2-S07·U2-S27~U2-S29·U2-S38·U2-S40·U2-S41·U2-S47·U2-S55~U2-S57·U2-S59·U2-S60·U2-S62·U2-S63. 정상/부분/취소/재시도/늦은 응답에서 참조 계보와 필수 조치를 대조하고 비밀/금지 출력0건을 요구한다. 음성 입력 자체는 보고서에 복사하지 않는다. 실제 CLI/로거/진단은 미실행이다.

<a id="u2-o02"></a>
## U2-O02 — 단계별 사실과 전체 세션 집계

대응: NFR7.2·NFR10.1. 소유: 생산 컴포넌트(단계 사실), OperationControl(원 요청 집계). 규칙: BR3.4·BR6.8·BR7.6·BR9.7.

승인/STORE/RECEIVE/VALIDATE/EVALUATE/CALENDAR는 다른 사실이다. 생산자/단계/작업·내용 참조를 검증해 자기 단계의 실제 결과만 집계한다. U3 STORE 성공·평가 실패 고지·검증 통과를 Calendar 성공으로 대신하지 않는다. 각 단계는 성공/미수행/차단/미확인과 사유를 보존하고 C08 기존 enum을 그대로 사용한다. 외부 C08의 실제 조회 위치/권한/현재성은 U2-O04의 미해소 조건이다.

분모는 원 요청의 모든 세션/대상이다. 이후 skip/과거/제외·실패·미확인을 빼서 성공률을 부풀리지 않는다. 요청 집합과 현재 처리 집합을 구분하고 각 세션의 원 의도/결과를 연결한다.

| 원 요청 결과 | 집계 및 C08 의미 |
|---|---|
| 모든 대상 실제 확인 성공, 효과 대상≥1 | 해당 단계 전체 SUCCESS |
| 일부 성공+실패/skip/미확인/제외 | 전체 PARTIAL, 각 결과 유지 |
| 전부 과거 skip 또는 효과 대상0 | BLOCKED, 전체 성공 아님 |
| 이전 미확인 효과가 과거가 됨 | OUTCOME_UNKNOWN/대조 유지, skip으로 단정 금지 |
| 실제 미생성 확인 뒤 시작≤현재 | 로컬 SKIPPED_PAST, C08 세션 BLOCKED+고정 정책 사유 |

C08에 SKIPPED enum을 추가하지 않는다. 과거 skip 자체는 고정 정책으로 재시도하지 않고 승인 내용/원 계획/실적을 보존한다. 처분에서 시간이 지나 미래 범위에서 제외된 세션도 원 처분 전체 APPLIED/SUCCESS로 축소하지 않는다. 소유자별 마지막 성공은 실제 확인된 범위만 갱신하고 sourceCollectedAt/generatedAt와 별도다.

검증 설계: U2-S27·U2-S50·U2-S52~U2-S60의 일부 성공·전부skip·효과0개·미확인·타 생산자 성공을 비교한다. 분모 축소/대리 성공/새 wire enum0건·필수 판정 전부 일치를 요구한다. 실제 C08 외부 노출은 미적격이다.

## U2-O03 — 보존 선택과 안전한 정리

대응: NFR10.2. 소유: DataAccessPolicy(보존 정책), OperationControl(MaintenanceRequest), 각 자료/효과 소유자(범위 결과). 규칙: BR1.1·BR3.7·BR4.10.

첫 설정에서 기존 보존 기간 선택을 받는다. 미설정은 자동 삭제 없음이며 새 고정 일수·자동 백업 정책을 만들지 않는다. DB 결과/의도·파일/진단에도 해당 사용자 선택과 보호 경계를 적용한다. 자료 증가/디스크 가득 참은 자동 삭제 동의가 아니다.

정리 입력은 확인된 MaintenanceRequest의 정확한 로컬/원격/일정 범위와 RetentionPolicy 개정이다. 소유자는 미확인 의도·원격 대조/연결·승인/충돌·다른 확정 자료의 참조를 먼저 검사한다. 아직 해결되지 않은 원 의도/대조 근거는 선삭제하지 않고 차단 이유를 반환한다. 삭제가 가능할 때만 소유 범위에서 처리하며 결과는 ownerOutcomes로 각각 남긴다. 제거는 예약 중단/프로그램 제거 범위이며 데이터 삭제로 해석하지 않는다.

부분 실패면 성공한 범위/잔존/미확인을 구별한다. 원격 사본/이력·휴지통 복원·실제 디스크 소실 복구를 보장하지 않는다. 정리 후 로컬 참조/불변 결과의 일관성은 [U2-R01](reliability-design.md#u2-r01)·[U2-R02](reliability-design.md#u2-r02)의 확정 규칙으로 검사한다. 미확인 삭제도 원 의도/고정 대상 대조가 먼저다.

검증 설계: U2-S03·U2-S32·U2-S59와 보존 미설정/영향 범위 불명/의도 미확인·정리 도중 중단. 자동 삭제0건·미해소 근거 선삭제0건·소유자 실제 결과/한계 고지 일치를 요구한다. 실제 정리/원격 삭제는 미실행이다.

## U2-O04 — 증거 등급과 활성화 보류

대응: NFR11.1·NFR11.2. 소유: OperationControl(표시), 후속 개발/품질 담당(통제 증거), 기능 모델/공유 규범·외부 인수 담당(각 미해소 조건). 규칙: BR1.3·BR2.1·BR5.8·BR6.5·BR8.1·BR8.2.

증거는 문서 정합 검사, 유한 합성 기대/실행, 통제 OS/하드웨어 실행, 실제 외부 환경/공급자 인수로 구별한다. 각 결과에 사례/방법·입력/설정/명세 digest·빌드/검사기/도구·환경/대상/버전·관측 경계/시각·정상/실패/미확인 수·기대와 차이·미수행/차단·한계를 붙인다. 설계 목표/기대값을 실행 통과로 쓰지 않는다. 실제 개인/건강 자료와 인증정보는 쓰지 않는다. 성능 p95/첫실행/예약/RSS 분모는 [U2-P04](performance-design.md#u2-p04), 세션 집계 분모는 U2-O02가 단일 기준이다.

| 미해소 조건 | 차단/다음 근거 | 담당 |
|---|---|---|
| Garmin P05 공식 인증/지표/기간·수정/페이지/한도 | 실제 수집 비활성, 공식 상세 계약/허용 시험 | 원천 연결/외부 인수 담당 |
| C06 인간 의도/전체 내용/행위·계보/철회 검증 | 자동 게시/변경/취소 차단, 적격 독립 승인 발급/검증 증거 | PlanAdmission/승인 프로필 담당 |
| C04 원 정책 신뢰·실제 클라이언트 현재성/철회 | 확인 불가 신규 전송 보류; 과거 사본 회수 보장 없음 | DataAccessPolicy/U3 실제 인수 담당 |
| 안전 규칙 근거/버전·단위/기간·한계 | SAFETY_BLOCKED, 의료 임계값 발명 금지 | 안전 프로필/PlanAdmission 담당 |
| 실제 ChatGPT 환경·Drive/GitHub/Calendar·C08 노출 | 해당 실제 기능 활성화/전체 인수 보류; 대역 성공 대체 금지 | 각 외부 인수 담당 |
| OpenAI 모델/지원 토큰 필드·가격/기간별 예산·품질 | 원격 평가 요청 보류, store=false 등의 형식만으로 해소 금지 | PlanEvaluation/외부 인수 담당 |
| 로컬/사설 대체 제공자·처리 위치/원격 우회·하드웨어 | 해당 유형 비활성, Ollama 제외; 원격만으로 FR8.2 완료 금지 | PlanEvaluation/외부 인수 담당 |
| ServiceConnection.serviceName에 chatgpt 없음 | 실제 ANALYSIS 경로 grant 바인딩 보류; enum/우회 매핑 추가 안 함 | 기능 모델/정책 담당 |
| RuntimeConfiguration.connectionIds의 활성 대상 의미 | 연결 참조 전체를 분석 게시 활성 대상으로 추정 금지 | 기능 모델/AnalysisPublication 담당 |
| 반복 소수 wire 정밀도·종료 규범 | 관련 계산 적격 보류; BigDecimal/새 반올림으로 해소 금지 | 기능 모델/공유 규범 담당 |
| 실제 OS/UID·로그아웃/복귀·credential/저장장치·시계/tzdb·Limits | 관련 운영 프로필 보류; manifest/통제 실행/경계 증거 필요 | U2 개발/품질/설치 담당 |

위 조건의 문서 존재·합성 통과만으로 READY/지원 완료를 표시하지 않는다. 모의 권한/승인/안전은 시험 입력임을 기록하고 제품 활성화 근거로 사용하지 않는다. 유한 사례의 금지 출력/잘못 허용0건과 정상 기대 일치는 모든 입력의 안전·의료 타당성·외부 권위를 보증하지 않는다. 현재 산출물의 정적 링크/표/ID/anchor/trace 검사는 문서 검사이며 제품 코드·OS 설치/실행·DB 복구·성능·실제 API/비용/안전 시험은 전부 미실행이다.
