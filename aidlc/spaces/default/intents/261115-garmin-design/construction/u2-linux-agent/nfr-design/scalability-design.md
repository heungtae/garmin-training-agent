<a id="u2-c01"></a>
## U2-C01 — 유한 실행 프로필과 입력 거절

대응: NFR8.7·NFR8.8. 소유: OperationControl(실행 계측/공통 자원), 각 수신/생산 소유자(문서/본문/작업 한도). 규칙: BR2.2·BR2.8·BR4.3·BR8.1·BR8.7·BR10.4.

다음은 Q&A의 초기 설계/합성 경계 시험 프로필이다. wire 필드·실제 공급자 쿼터·계정 토큰 한도·제품 총 자료량 상한을 바꾸지 않는다. 실제 정책/기간별 호출·비용/토큰 한도가 더 엄격하면 이를 적용하고 미확보면 관련 요청을 보류한다.

| 자원 | 상한과 적용 시점 | 한도 도달 결과 |
|---|---|---|
| 한 문서/HTTP 요청·응답 | 입력·출력 각각8MiB; 원시 및 복호화/압축 해제 후 각각 검사 | Content-Length만 신뢰하지 않음; 본문 수신/생산을 중단하고 RESOURCE_LIMIT/미완료 |
| 실행 누적 입출력 | 입력·출력 각각64MiB; 여러 문서/모든 시도·재시도 합산 | 다음 작업 전 예산 확인, 커서/pending 보존 후 정리 |
| JSON 깊이 | 루트 컨테이너1, 배열/객체마다+1, 최대64 | 파싱 단계에서 거절; 평탄화/잘림 없음 |
| 일반 숫자 parser 자원 | 부호/소수점 제외 숫자 최대1024자리; 큰 값 생성 전 검사 | 초과 RESOURCE_LIMIT; 아래 GTA-NUMERIC-1 의미 범위를 완화하지 않음 |
| 원천/정확 합계 의미 범위 | 정수부 최대30자리·소수부 최대18자리 | 초과 DATA_INVALID; 합계를6자리로 반올림/절단하지 않음 |
| 정확 유리수 계산 자원 | 각 연산 전 중간 분자/분모 각각 최대256자리 검사 | 초과 RESOURCE_LIMIT; 기본 정밀도 나눗셈/이진float 우회 없음 |
| 활성 실행 | 목적별1개, COLLECTION_SYNC/PLAN_CHECK 합계 최대2개 | 같은 목적은 실행권 최대5초 후 중복 억제/대기 결과 |
| 목적별 하위 작업 | 동시 네트워크1개·CPU 하위 프로세스 최대1개 | 활성 작업·대기 모두 전체 시간/RSS/예산에 포함 |
| 메모리 대기 묶음 | 목적별 식별자 최대32개 | 초과 작업은 영속 pending/원천 cursor에 남기고 다음 묶음으로 진행 |

입력 누적은 문서가 DB/메모리 처리 경계에 들어오는 실제 바이트를, 출력 누적은 생성/전송하는 실제 바이트를 보수적으로 센다. 동일 바이트의 raw/해제 후 표현은 각 경계 모두 제한하며 보수적 계측으로 상한을 느슨하게 만들지 않는다. 경계별 센서/방식은 후속 실행 증거에 기록한다. Content-Length 미제공·chunked·압축 폭증·LLM 내부 JSON도 예외가 아니다. 메모리 한도는 바이트 한도만으로 보장되지 않으므로 [U2-P04](performance-design.md#u2-p04)의 실제 RSS 계측을 병행한다.

LLM 문맥은 허용 입력의 실제 모델별 토큰 제한과 양의 출력 토큰 한도를 추가 적용한다. 8MiB 이내라는 이유로 모델 적격으로 판정하지 않는다. 허용 분할은 등록 C03 Detail/승인 원내용 불변 규칙 안에서만 수행하고, 안전/필수 근거를 자르거나 다른 제공자로 우회하지 않는다. 한 항목도 등록 형식/한도에 맞출 수 없으면 명시 보류한다.

검증 설계: U2-S08·U2-S09·U2-S18~U2-S20·U2-S34·U2-S48·U2-S62·U2-S72와 NUM-01~NUM-16에 각 상한 직전/동일/초과, 압축/해제 후 초과, 깊이63/64/65·일반 parser 숫자1023/1024/1025자리·큐31/32/33을 적용한다. 계산 의미 경계는 정수부30/31자리·소수부18/19자리·합계 자리 증가와 중간 분자/분모256/257자리를 별도로 검사한다. parser가 허용한 값도 의미 범위 초과면 거절하며 DATA_INVALID/RESOURCE_LIMIT를 구별한다. 허용 정상의 필수 판정 일치와 조용한 잘림/누락/무제한 대기0건을 요구한다. 실제 라이브러리 메모리/CPU 한계는 미검증이다.

<a id="u2-c02"></a>
## U2-C02 — 중첩 실행과 소유자별 경쟁 제어

대응: NFR5.2·NFR8.3·NFR8.6. 소유: OperationControl(목적 실행권), 각 엔티티 소유자(유일성/개정/의도). 규칙: BR1.6·BR2.4·BR3.3·BR7.7·BR9.4.

예약/즉시/복구는 동일 사용자/PC/목적 workKey의 OS 실행권을 최대5초만 기다린다. 같은 목적의 추가 요청은 실행을 중복 시작하지 않고 DUPLICATE_SUPPRESSED/대기 조치를 남긴다. lock 손실은 새 실행 허가를 뜻하지 않으며 ExecutionRecord와 미완료 의도를 대조한다. systemd가 활성 서비스의 추가 활성화를 억제해도 앱의 영속 멱등성을 대신하지 않는다.

두 목적은 독립 활성화될 수 있으나 같은 ActivityRecord/분석 대상/논리 세션을 공동으로 쓰지 않는다. 각 소유자의 repository가 [U2-R01](reliability-design.md#u2-r01)의 기대 개정 CAS와 유일 키로 현재 내용을 확정한다. 원천은 sourceConnectionId+sourceActivityId, Calendar는 원 의도+고정 이벤트 ID·세션 관계를 기준으로 대조하며 opaque ID를 가공하지 않는다. 경합/개정 실패는 최신 상태를 읽어 현재 정책/계보를 재검사한 뒤 재개 후보로만 돌린다. 최신 etag/새 객체로 충돌을 우회하지 않는다.

예산 예약/nextAllowedAt은 [U2-R04](reliability-design.md#u2-r04)의 공통 영속 집계로 두 목적을 함께 제약한다. 자원은 같은 slice의 보조 보호와 실제 CLI/두 목적/자식 RSS 합산을 적용한다. 한 목적의 네트워크 실패는 다른 목적의 확정 성공을 취소하지 않지만 DB/비밀 보호 자체가 실패하면 영향을 받는 새 효과는 함께 차단한다.

검증 설계: U2-S04·U2-S28·U2-S39·U2-S59에서 같은 목적의 예약/즉시 충돌·두 목적의 동일 원천/세션 CAS·전송 전후 중단을 교차한다. 논리 중복/기존 확정 손실0건·실행권5초·합산RSS≤1GiB·현재성 재검사 기대를 확인해야 한다. OS 잠금/프로세스 그룹 경계는 미실행이다.

<a id="u2-c03"></a>
## U2-C03 — 자료 증가·부분 처리·저장 여유

대응: NFR8.7·NFR8.8·NFR10.2. 소유: ActivityCollection(페이지/커서), AnalysisPublication(Detail/루트), DataAccessPolicy(보존), OperationControl(집계). 규칙: BR1.7·BR2.2·BR3.7·BR4.3·BR4.9.

10,000활동/300세션은 고정 시험 부하이며 최대 지원 용량이 아니다. 원천 페이지·상세는 유한 묶음으로 읽고 확정 활동/실패 범위·목록 완료 범위를 분리한다. 전체 목록 완료가 아닌 범위는 완료 cursor로 넘기지 않는다. C03은 한 문서가 한도를 넘기기 전에 등록 Detail들로 나누고 각 고정 내용/계보/합계 확인 뒤 루트를 마지막에 게시한다. Detail/루트조차 한도를 만족하지 못하면 pending/실패 조각을 남기며 일부만 COMPLETE로 만들지 않는다. 자세한 확정 순서는 [U2-R05](reliability-design.md#u2-r05)다.

100회 실제 전송/570초 cutoff/누적64MiB 때문에 한 실행에서300세션의 외부 처리가 끝나지 않아도 나머지는 원 요청에 남긴다. 아직 처리하지 않은 항목과 미확인 효과를 메모리 큐에서 버리지 않고 소유자의 기존 영속 미완료/커서·의도에 연결한다. 다음 예약은 영속 예산/대기와 현재 근거를 다시 확인한다. 전체 완료 SLA·성장률·새 디스크 최대치를 만들지 않는다.

용량 부족은 쓰기 오류/미완료 건수·지연·메모리·자원 초과 건수로 드러낸다. 디스크 여유가 파일/DB commit을 감당하지 못하면 [U2-R01](reliability-design.md#u2-r01)·[U2-R02](reliability-design.md#u2-r02)에 따라 이전 유효본을 유지하고 새 효과를 차단한다. 자동 삭제/클라우드 전환/자동 백업을 용량 회복으로 사용하지 않는다. 첫 설정 보존 선택·미설정 자동 삭제 없음과 미해소 의도 우선 보존은 [U2-O03](observability-design.md#u2-o03)을 따른다.

검증 설계: 빈 목록/역순·분할·기준 초과 합성 자료, 한도 직전/동일/초과, 디스크 가득 참/읽기 전용, 세션 처리 도중 예산 소진을 U2-S08·U2-S09·U2-S18~U2-S21·U2-S28·U2-S32·U2-S48·U2-S62로 확인한다. 모든 허용 정상·명시 미완료 판정이 일치해야 하며 기준 부하는 성능 목표도 만족해야 한다. 부하/장치/대량 제품 시험은 미실행이다.
