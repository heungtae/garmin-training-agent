## 운영 지표와 판정 경계

로컬 기록/CLI에서 목적별 예정/실제 시작·지연 사유, 마지막/다음 실행(null 포함), 결과/마지막 성공, 미완료 범위·커서, 요청/시도 수·영속 예산 예약/남은 값·다음 허용 시각, 타임아웃/중복 억제·원격 미확인/충돌, 복구 조치를 확인할 수 있어야 한다. 외부 본문·민감 수치·비밀과 보호 보관 참조는 수집/표시하지 않는다. 로컬 저장 용량·정리 실패와 예산 미확인도 성공으로 덮지 않는다. 구체 로그 저장 형식/보호·도구/계측 주기는 [기술 결정](tech-stack-decisions.md)의 후속 선정 조건이다.

SLI의 분모는 [성능 요구사항](performance-requirements.md)의 고정 측정 20회·첫 실행 별도 5회·예약 조건별 5회 및 원 요청 전체 세션 집합이다. 중복 억제는 예약 시작 성공의 분모에서 분리해 건수/사유를 보고하고, Calendar skip은 원 요청에서 제거하지 않는다. 오류/한도 초과·미완료/미확인·권한/정책/승인/안전 차단은 한국어 조치로 드러낸다. 별도 가용성 백분율 SLA나 원격 경보를 도입하지 않는다.

## 증거의 내용과 현재 한계

후속 시험 기록에는 사례 ID·입력/설정/명세 digest·빌드/검사기/도구·환경·관측 범위/시각·정상/실패/미확인 수·정해진 기대값과 차이를 남긴다. 음성 입력 표식은 보고서에 echo하지 않고 사례 ID·필드 경로·검출/요청 건수만 남긴다. 실제 개인정보·건강 자료·계정 비밀로 검증하지 않는다.

이번 단계의 UTF-8·링크·표·ID·traceability 검사는 문서 검사다. 실제 에이전트/스케줄러/복구·안전 필터·외부 API/승인·권한·정책 현재성·하드웨어/모델/비용/시간대 적격성은 미실행·미해소다. 고정된 합성 사례의 성공도 모든 입력 안전 보장이나 실제 공급자 인수 결과가 아니다.
