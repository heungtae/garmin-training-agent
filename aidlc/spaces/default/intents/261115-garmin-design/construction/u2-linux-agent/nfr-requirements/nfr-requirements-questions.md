# U2 Linux 에이전트 — 비기능 요구사항 확인

- 단위: U2 `u2-linux-agent` (`service`), 깊이/검증 전략: Standard.
- 근거: [기능 명세](../functional-design/functional-spec.md), [업무 규칙](../functional-design/rules.md), [상류 요구사항](../../../inception/requirements-analysis/requirements.md), [교환 계약](../../../inception/contract-design/contract-summary.md).
- 현재는 QUESTION-ONLY이며 비기능 요구사항 본문·제품 코드·설치·외부 호출을 수행하지 않는다.

## 현재 적용 입력

리뷰 반영 요청과 승인된 최신 기능 설계에 따라 chatgpt FINAL_READER·독립 원 동의/C04 매핑, 등록 connectionIds와 analysisTargets/planInboxConnectionId 분리, GTA-NUMERIC-1/NUM-01~16을 적용한다. 아래 문답은 이전 생성 시 기록이며 원 답변을 다시 작성하지 않는다. 과거 세 모델/수치 공백에 관한 설명은 당시 상류 상태이며 현재는 보완된 모델과 남은 실제 실행 증거를 구분한다. 기존 성능·복구 수치와 미해소 승인·안전·외부 인수 조건은 유지한다.

## 기존 결정과 미해소 조건

한 사용자/한 PC, Rust·Ubuntu 24.04 이상·한국어 CLI·로그아웃 중 예약 실행을 유지한다. 수집/동기화 기본 1시간과 계획 확인 기본 15분은 독립 설정이다. 이 주기는 외부 서비스 응답 완료나 항상 켜짐/네트워크 가용성 SLA가 아니다.

합성 자료만 사용하고 비밀/금지 자료 출력 0건·미허용 신규 요청 0건·중복/강제 종료/디스크 실패의 기존 확정 자료 손실 0건을 지정 시험의 합격 조건으로 구체화한다. 무한 대기/재시도를 막고 원격 미확인은 원 의도/고정 ID로 대조하며 승인/저장/수신/평가/Calendar 결과를 구별한다. 허용 경로별 정확한 공유 집합·기간/시간대·엄격 파싱·전체 JSON digest와 실제 증거의 구분은 승인 계약을 따른다.

보존 기간은 첫 설정의 사용자 선택이며 미설정 시 자동 삭제하지 않는다. 예산 상한/마감 미지정과 유료 사용 전 비용 조건 확인을 유지한다. 실제 LLM 모델/비용/로컬·사설 처리 환경·대체 제공자, 승인 검증/정책 현재성·안전·외부 프로필 적격성은 미해소 조건이다. Ollama는 제외한다. 원격 검증 대상 OpenAI 결정만으로 사용/결제나 실제 연동을 승인하지 않는다.

앞서 승인된 기능 설계의 ChatGPT 동의 대상 모델 부족, 연결 목록 의미의 모호함, 반복 소수 계산 정밀도 미정, 다른 단위의 기존 검토 한계를 해결됐다고 바꾸지 않는다. NFR 문서의 요구조건과 실제 기존 모델 보완/제품 적격성을 구별한다.

## Q2. [운영 담당자] 로컬 응답 시간·메모리·예약 시작 지연 목표

Q1에서 선택한 시험 환경과 부하에서 비교할 초기 합격 목표다. 제품 성능 실적이나 실제 외부 서비스의 완료 시간 보장이 아니다. 고정 합성 입력·설정·빌드·명세 및 측정 도구/버전을 증거에 남긴다.

A. 아래 제안 목표로 설계한다.
   - 네트워크를 호출하지 않는 로컬 상태/설정 조회 CLI: 프로세스 시작부터 종료까지 p95 2초 이내.
   - 로컬에 확정된 운동 10,000건의 분석 재계산·로컬 산출물 확정: p95 60초 이내. 외부 수집/게시·LLM 호출은 이 시간에 포함하지 않는다.
   - 에이전트와 하위 프로세스의 합산 상주 메모리: 측정 실행 전 구간에서 1 GiB 이하. 두 예약 목적이 겹치는 시험은 양쪽을 합산한다. 로컬/사설 LLM 추론 서버는 별도 프로필이며 제외 사실을 표시한다.
   - PC가 켜져 있고 절전 상태가 아니며 필요한 실행 조건과 실행권을 확보할 수 있는 경우: 예약 예정 시각부터 실행 시작 기록까지 60초 이내. 로그아웃 상태도 검증한다. 중복 실행으로 억제된 요청은 별도 상태이며 시작 성공/지연 분모에 숨겨 넣지 않는다. 전원 꺼짐·절전·실행권 대기 등의 지연은 사유/지연 시간과 복귀 처리를 별도로 표시한다.
   - CLI/분석은 사전 준비 5회 후 측정 20회 각각의 시작/종료 경계를 단조 시계로 측정하고 p95는 정렬한 20개 중 19번째 값으로 판정한다. 준비 실행과 실패/타임아웃 건수도 보고하며 기대 정상 시험에서 실패가 있으면 p95만으로 합격시키지 않는다. 첫 실행/캐시가 비어 있는 실행은 별도 5회를 전부 보고하고 준비된 실행과 합치지 않는다. 메모리는 준비·측정·첫 실행·동시 실행 시험을 모두 검사한다. 예약 지연은 부하 없음/기준 부하/로그아웃별 고정 5회가 각각 전부 60초 이내인지 검사한다.
B. 목표 수치를 직접 지정한다. CLI 응답·분석 시간·합산 메모리·예약 시작 지연 중 변경할 값을 알려 준다.
X. Other (please specify)

[Answer]: A. 아래 제안 목표로 설계한다. 로컬 조회 CLI p95 2초 이내, 로컬 분석·산출물 확정 p95 60초 이내, 합산 상주 메모리 1 GiB 이하, 실행 조건 충족 시 예약 시작 지연 60초 이내. 위 측정 범위·방법과 제외/실패 보고 조건을 함께 적용한다.

## Q3. [운영 담당자] 유한 대기·재시도와 로컬 재시작 복구 목표

외부 서비스가 느리거나 응답을 잃어도 실행이 무한 대기하지 않아야 한다. 아래 수치는 설계/통제 시험 프로필이며 실제 서비스 응답 시간·허용 호출량·지원 적격성을 보장하지 않는다. 실제 공급자/모델 정책·권한·가격/예산을 확인하지 못한 기능은 이 값만으로 활성화하지 않는다.

A. 다음의 제한·복구 목표로 설계한다.
   - 외부 요청은 연결 제한 10초, 요청 전체 제한 일반 API 30초·LLM 평가 120초로 제안한다. 요청 전체 제한은 연결·응답 본문 수신까지 포함하며 현재 실행의 남은 시간보다 길게 잡지 않는다. 로컬/사설 모델은 별도 실제 프로필 적격성이 필요하다.
   - 한 논리 요청은 최초 시도를 포함해 최대 3회다. 재시도 가능한 확인된 일시 실패만 대상이며 각 재시도 전에 정책/권한·예산·현재 내용을 재확인한다. 쓰기/과금 결과 미확인은 먼저 대조하며 무조건 재전송하지 않는다.
   - 예약 목적별 한 실행은 정리/미완료 상태 기록을 포함해 최대 10분, 외부 요청 총 100회 이하를 시험 프로필로 삼는다. 읽기·메타데이터·쓰기·대조·재시도·LLM 등 실제 전송을 모두 차감하고 시작 전에 영속 예산을 예약한다. 두 목적을 합친 서비스별 공급자 한도와 기간별 호출/비용 예산도 별도로 적용한다. 페이지/일부 자료만 처리했을 때 요청 범위·커서를 완료로 전진시키지 않는다.
   - HTTP 429 등의 공급자 대기 지시는 지킨다. 대기 지시가 남은 실행 시간을 넘으면 다음 허용 시각·미완료 사유를 영속 보존하고 이번 실행을 종료한다. 다음 예약/즉시 실행·재시작으로 대기 시각 또는 기간별 호출/비용 한도를 초기화하지 않는다. 구체 지수 백오프/지터는 이 범위와 공식 정책을 만족하도록 NFR Design에서 선정한다.
   - 중복 실행권 대기는 최대 5초 후 대기/중복 억제 상태를 표시하고 종료한다. 로컬 하위 프로세스는 최대 60초와 실행의 남은 시간 중 작은 제한을 적용한다. 실행 정리 시간을 미리 확보하며 프로세스 종료만으로 원격 효과 취소/불발을 자칭하지 않는다.
   - Q1 기준 부하와 정상 읽기 가능한 로컬 저장장치에서, 재시작 프로세스 시작부터 미완료 로컬 기록·확정 커서·미확인 외부 의도를 식별하고 다음 대조/재개 또는 보류 상태를 표시하기까지 60초 이내를 목표로 한다. 원격 대조 완료·재수집·LLM·게시 완료는 포함하지 않는다. 현재 승인/정책·안전·권한 재검사 없이 외부 효과를 재개하지 않는다.
   - 통제된 중복 실행·저장 중 강제 종료·디스크 가득 참/읽기 전용·응답 유실 시험에서 기존 확정 자료 손실과 논리 중복 효과 0건을 요구한다. 원격 결과를 읽을 수 없으면 미확인으로 보존한다. 실제 디스크 소실·손상 복구, 외부 사본 삭제/복원, 별도 자동 백업의 성공을 이 기준으로 보장하거나 새 기능으로 추가하지 않는다.
B. 시간·횟수·복구 목표를 직접 지정한다. 변경할 항목과 값을 알려 준다.
X. Other (please specify)

[Answer]: A. 다음의 제한·복구 목표로 설계한다. 연결 10초, 일반 API 요청 전체 30초·LLM 평가 120초, 최초 포함 최대 3회, 예약 목적별 실행 정리 포함 10분·전체 외부 요청 100회 이하, 중복 실행권 대기 5초, 하위 프로세스 60초, 기준 부하의 로컬 복구 상태 표시 60초 이내. 위 영속 대기/예산·미확인 대조·복구 범위와 실제 프로필 적격성 조건을 함께 적용한다.

## 이후 상세화와 확인

Q1 답변을 반영해 로컬 CLI/분석 처리와 예약 실행 지연, 자원 상한·대량/동시 접근, 유한 호출/하위 프로세스/대기·재시도, 로컬 확정/복구·단계별 진단 및 기술 선택의 검증 가능한 목표를 정리한다. 외부 공급자 실제 지연/호출 한도와 로컬 추론 적격성은 별도로 남기고 임의 숫자를 운영 기본값으로 활성화하지 않는다. 추가 사용자 판단이 필요한 충돌/모호함은 좁은 후속 질문으로 해소하며, 산출물 작성 전 답변 요약을 별도로 확인한다.

## 답변 정합성과 작성 경계

- Q1~Q3은 초기 설계/통제 시험 목표로 일관된다. 한 실행 10분에는 개별 요청·대기·하위 프로세스와 종료 정리가 모두 포함된다. 개별 제한은 남은 실행 시간과 정리 여유를 적용해 더 짧게 제한하며 시간 초과를 성공으로 바꾸지 않는다.
- 1 GiB는 에이전트 및 관련 하위 프로세스 합산이며 동시 예약 목적도 합산한다. 별도 로컬/사설 LLM 추론 서버의 자원·지연/지원은 미선정 프로필로 따로 검증한다.
