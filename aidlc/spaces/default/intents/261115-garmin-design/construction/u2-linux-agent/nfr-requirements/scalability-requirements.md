# U2 Linux 에이전트 부하와 용량 요구사항

## Sources

근거: [기능 명세](../functional-design/functional-spec.md), [업무 규칙](../functional-design/rules.md), [상류 요구사항](../../../inception/requirements-analysis/requirements.md), [교환 계약](../../../inception/contract-design/contract-summary.md), [확정 Q1~Q3](nfr-requirements-questions.md). 한 사용자·한 PC의 자료 증가/예약 중첩/유한 자원만 다룬다. 다중 테넌트·다중 PC·수평 확장·클라우드·GUI/운영 대시보드를 새 요구로 추가하지 않는다.

## 부하 해석

기준은 합성 운동 10,000건·계획 세션 300개와 [성능 요구사항](performance-requirements.md)의 CPU 2코어·RAM 4 GiB·SSD·Ubuntu 24.04다. 기준 초과는 제품 최대 용량 선언이 아니다. 한도 경계 시험은 NFR Design에서 유한 bytes/depth/문맥/큐/동시성 프로필을 선정한 뒤 그 실제 값 직전/동일/초과를 사용한다. 근거 없는 최대 건수·디스크 크기·성장률·처리량을 발명하지 않는다.

## 용량 부족과 성장 처리

자원/호출 한도 도달은 미완료 범위·확정 커서·다음 대기 시각을 유지하고 실행을 종료할 이유다. 더 큰 부하를 처리하려고 안전/동의·승인 검사나 전체 페이지 확인을 생략하지 않는다. 두 목적의 서비스별 한도·기간별 호출/비용 예산은 공통 영속 집계로 적용하며 [복구 요구사항](reliability-requirements.md)의 NFR8.10~NFR8.11을 참조한다.

보존 기간은 첫 설정의 사용자 선택이고 미설정이면 자동 삭제하지 않는다. 자료 증가/디스크 부족을 자동 삭제 동의로 해석하지 않는다. 보존·정리의 상세 정의는 [관측 요구사항](observability-requirements.md)의 NFR10.2, 디스크 오류 보존은 [복구 요구사항](reliability-requirements.md)의 NFR5.3을 따른다. 확장 필요성은 경계 초과 건수·미완료·소요/메모리·저장 실패로 판단하며 자동 클라우드 전환이나 새 서비스 도입을 수행하지 않는다.

## 검증 한계

부하/메모리/대량/로그아웃·동시성 제품 시험은 미실행이다. 기준 환경의 성능 지원, 실제 API 처리량·쿼터·페이지 한도, 로컬 추론 용량을 입증하지 않았다. 후속 NFR Design에서 프로필과 계측 수단을 선정하고 Code Generation/Build and Test에서 독립 합성 검사를 수행한다. 실제 공급자 조건이 없으면 프로필 활성화 보류를 유지한다.
