- 근거: [단위 정의](../../../inception/units-generation/unit-of-work.md), [요구사항 배정](../../../inception/units-generation/unit-of-work-story-map.md), [상세 요구사항](../../../inception/requirements-analysis/requirements.md), [컴포넌트](../../../inception/domain-design/components.md), [공통 교환 계약](../../../inception/contract-design/contract-summary.md).
- 범위: CoachingWorkflow의 기존 엔티티 6개와 배정 기능 요구사항 33개의 기능 설계 입력. 이번 단계는 질문·요약 확인이며 제품 코드·설치·외부 호출을 수행하지 않는다.

## 추가 질문 분석

별도의 사용자 판단이 필요한 신규 질문은 없다. 목표 정보 재사용/부족값 확인, 자료 접근 실패/추정 구별, 러닝 계획·수정·명시적 승인 의사·저장 확인, 새 버전 새 승인과 보류 정책은 승인된 요구사항과 계약에서 이어받는다.

U3의 소유 엔티티는 TrainingGoal, AuthoredPlanVersion, AuthoredSession, ApprovalDeclaration, PlanTransferReceipt, AuthoredPlanInstruction이다. U1의 교환 명세, U2의 원 공유 정책·원천 운동·승인 검증·평가·Calendar 실행 소유를 가져오지 않는다.

## Consolidated Summary Confirmation

- U3의 기존 엔티티 6개·배정 기능 요구사항 33개를 대화/작성 규칙·데이터 모델·상태 전이·정상/실패 흐름과 추적성으로 구체화한다. 실제 수집·승인 검증·LLM 평가·Calendar 실행은 U2의 책임이다.
- 필요한 목표 정보만 확인하고 기존의 신뢰할 정보를 재사용한다. 상충·미정은 구별하고 구조화 목표 요약과 수정 기회를 제공한다.
- 허용된 분석 자료의 출처·기간·최신성·완전성을 확인하고, 읽기 실패·미수집·정상 0건·비공개·부분 자료와 추정 기반을 구별한다. 원 정책의 신뢰/현재성·공유 허용을 확인하지 못하면 관련 신규 전송을 보류한다.
- 러닝 계획의 기간·주차·세션·휴식·강도/단위·수행 내용을 완전하게 작성한다. 사용자가 등록한 고정 운동과 가능 시간·회복을 고려하고, 부족한 자료/근거·안전 한계와 조정 후보를 설명한다. 미승인 변경이나 근거 없는 수치를 적용하지 않는다.
- 정확한 작성 버전/전체 내용·정책·행위에 명시적 사용자 승인 의사를 연결한다. 작성본·승인 선언·실제 승인 검증을 분리하고 새 내용에는 새 버전/새 승인을 요구한다. 기존 승인본·실제 운동은 보존한다.
- 지원이 확인된 직접 또는 허용 수동 경로로 버전별 JSON을 Drive에 저장하고 위치·버전·내용을 재확인한다. 저장·수신·검증·평가·Calendar 결과를 독립 안내하며 미확인/부분/실패를 성공으로 표시하지 않는다.
- 폐기·교체·게시 취소는 정확한 대상·승인 행위·미래 영향 범위를 전달하는 흐름으로 설계한다. 외부 자료의 지시가 실행/공유/승인 권한을 확대하지 못하게 한다.
- 실제 ChatGPT 계정/웹/모바일 읽기·쓰기 지원, 적격 승인 경로·정책 최신성·외부 연결과 안전의 기존 미해소 조건을 유지한다. 확인 후 entities.md·rules.md·functional-spec.md·traceability.json의 설계 입력으로 사용하며 실제 외부 호출·제품 구현/인수는 수행하지 않는다.
