- 대상: U3 `u3-chatgpt-workflow`, kind `spec`, Standard. 직접 배정된 상류 NFR1~NFR11을 모두 구체화한다.
- 근거: [기능 명세](../functional-design/functional-spec.md), [업무 규칙](../functional-design/rules.md), [상류 요구사항](../../../inception/requirements-analysis/requirements.md), [공유 계약](../../../inception/contract-design/contract-summary.md), [확인한 Q&A](nfr-requirements-questions.md).

## 소유 범위와 측정 원칙

U3는 대화·목표/계획 작성·승인 의사·Drive STORE 관측과 확인한 독립 결과의 안내를 맡는다. 모델 출력·외부 파일·C06 선언·오류/조치 문구는 불신 자료다. 승인 의사 수집과 U2의 독립 `ApprovalProof`, `RECEIVE`, `VALIDATE`, `EVALUATE`, `CALENDAR` 판정을 구별한다. U3는 PC 직접 실행·게시 권한이나 별도 서버를 소유하지 않는다. C05는 언제나 `PROPOSAL`이다.

표의 0건·전수 일치는 아래 U3-01~39와 B3-01~11 및 고정 U1 공통 사례의 모든 지정 하위 조건에 대한 유한 검사 목표다. 아직 워크플로 실행기·제품 시험을 실행하지 않았다. 미실행·자료 누락·판정 불명은 합격이 아니다. 구조/의미 검사·대화 기대값·실제 외부 권한/효과를 분리 보고하며 보편 보안·의료 안전·인간 의도·플랫폼 지속성을 보증하지 않는다.

시험에는 합성 자료만 쓴다. 합성 비밀·금지자료 표식은 음성 입력에만 넣고, 출력·보고·오류·스크린샷·로그에는 원문이나 표식을 echo하지 않는다. 보고에는 사례 ID·검사한 필드 경로·검사/위반 건수만 남긴다. 합성 적격 입력은 기대 분기를 정의하기 위한 조건이며 실제 승인·정책·도구 적격성을 발급하지 않는다.

## 공통 경계 검사 자료의 완전 조건

## 성능·확장·가용성·관측의 적용

U3에 새 서버 응답 SLA·가용성 백분율·처리량/RSS·운영 대시보드를 부여하지 않는다. U2의 하드웨어·p95·예약·요청 시간/횟수·로컬 복구 수치는 U3 클라이언트 보장이 아니다. U3는 읽은 범위·미완료·마지막 확인·중단 이유·다음 조치를 대화와 교환 자료로 표시한다. 플랫폼 장시간 실행·모든 컨텍스트 기억·지속 보관은 실제 환경 증거 없이 약속하지 않는다. 실제 시간/크기/호출 한도가 미설정·미적격이면 신규 요청을 보류한다.

## 남는 한계와 후속 인수 조건

- NFR Design은 실제 도구별 유한 프로필의 값·강제/확인 방법·백오프/지터, JSON/Schema/JCS/SHA-256·정밀 Decimal·tzdb 검증 기술의 적격 조건을 선정한다. 구현 라이브러리/버전·DB·비밀 보호·스케줄러를 이 문서에서 확정하지 않는다. U3 자체 검증은 U1 고정 명세와 자기 자료로 독립 수행한다.
- 실제 ChatGPT 개인 계정 웹/모바일 지원·도구 바인딩, 원 정책 신뢰/현재성/철회, C06 인간 의도·내용/행위·현재 승인/철회 결합의 독립 적격성, Drive 전체 재읽기/지속 저장·동시성, C08 위치/권한/생산자/최신성, 실제 GTA-NUMERIC-1 계산 도구 부합·tzdb·안전 프로필은 미해소다. 직접/수동 모두 해당 조건 해소 전 관련 신규 요청을 보류한다.
- 상류 기능 모델은 Intensity를 BR3.6으로 정정했고 공통 계산 규범 GTA-NUMERIC-1을 반영했다. ChatGPT 원 동의의 C04 표현과 목적별 선택은 보완된 상류 경계를 따르되 실제 계정·경로·현재성 증거로 확대하지 않는다. ConsumerBinding의 소비자 개정 식별 한계는 유지한다.
- Garmin 공식 상세 계약, 초기 원격 OpenAI의 모델/비용/호환성, 로컬/사설 대체 제공자·실제 처리 위치/하드웨어는 미확인이고 Ollama는 제외한다. U2 실제 수신·평가·Calendar 효과와 의료 안전성은 이 단위의 문서 검사로 해소되지 않는다.
- 보존/삭제는 기존 사용자 선택과 정확한 영향 확인을 따른다. 새 보존 기간·자동 삭제/백업·인증/법정 준수 완료·의료 임계값·추가 PC 승인 정책을 만들지 않는다. 미설정이면 자동 삭제하지 않으며 원격 사본 자동 회수/복구도 보장하지 않는다.

문서 검증은 ID/근거/사례/표/링크/UTF-8·traceability의 정적 일치 확인이다. U3-01~39·B3-01~11·실제 계정/API·승인·안전·성능의 제품 실행 결과와 구별한다.
