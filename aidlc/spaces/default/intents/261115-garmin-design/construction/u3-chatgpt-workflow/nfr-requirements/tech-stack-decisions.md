- 대상: U3 `u3-chatgpt-workflow`, kind `spec`.
- 근거: [기능 명세](../functional-design/functional-spec.md), [업무 규칙](../functional-design/rules.md), [상류 요구사항](../../../inception/requirements-analysis/requirements.md), [공유 계약](../../../inception/contract-design/contract-summary.md), [확인한 Q&A](nfr-requirements-questions.md).
- 상세 NFR의 정의와 합격/실패 기준은 [보안·품질 요구사항](security-requirements.md)에만 둔다. 아래 참조는 새 상세 ID 정의가 아니다. [추적성](traceability.json)으로 상류 11개에 연결한다.
- 이 문서는 기존 확정 선택을 계승하고 미선정 구현 기술의 조건을 후속 NFR Design으로 넘긴다. 새 기술 추천/버전 선정·실제 지원 검증·설치·코드·외부 호출·유료 사용을 수행하지 않는다.

## 보존하는 범위와 미해결 위험

목표·계획/선언·처분 요청은 버전별 일반 JSON으로 지속 보관해야 하나 실제 플랫폼 지속 조회·재읽기 성공은 아직 입증하지 않았다. 사용자 보존 기간 미설정 시 자동 삭제 없음, 삭제/취소는 정확한 영향 확인, 원격 잔존/복구 한계 안내를 유지한다. U3에 새 백업/삭제 정책을 만들지 않는다.

기존 entities의 강도 규칙 참조 BR3.5와 규범 BR3.6의 불일치는 상류 승인된 미해결 위험이다. 여기서 모델 수정/해결을 선언하지 않는다. ConsumerBinding 개정 식별·ChatGPT 동의 대상 모델 등 기존 한계도 실제 적격성을 증명하지 않는다.

NFR Design은 미선정 기술의 조건과 대안을 구체화할 책임이 있으며, 실제 계정/권한·승인/정책 현재성·안전·API·수치 정밀도/tzdb 적격성은 그때도 별도 실행 증거가 있어야 해소된다. 이 문서에 새 라이브러리·제공자 추천 또는 현재 외부 제품 지원 주장을 추가하지 않았으므로 기존 계약의 공식 링크를 현재 기능 검증 실적으로 취급하지 않는다. 현재 수행 대상은 문서의 ID/링크/표/추적성 정적 검증뿐이다.
