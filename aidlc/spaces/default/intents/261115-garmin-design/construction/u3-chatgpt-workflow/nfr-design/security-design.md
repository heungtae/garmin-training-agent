# U3 ChatGPT 워크플로 보안·품질 설계

U3 `u3-chatgpt-workflow`의 한국어 대화·교환 문서 설계다. 구현·설치·계정/API 호출·제품 시험 결과가 아니다. 아래 정상 절차는 각 선행조건의 실제 증거가 확보된 경우에만 적용한다. 현재 적격 도구·원 정책·승인·안전 경로가 미해소이므로 관련 외부 호출을 보류한다.

## 처리 순서와 공통 실패 규약

환경/도구 적격(SD3-01) → 매 요청 정책/실제 경로(SD3-02) → 비밀·불신 자료 경계(SD3-03) → 엄격/결정적 전체 내용(SD3-04) → 분석 완전성 또는 목표/완전 계획/안전(SD3-05~08) → 새 버전·정확한 승인 의사·단일 행위(SD3-09~11) → 직접/수동 동일 STORE 확인(SD3-12) → 중단·원격 대조(SD3-13) → 독립 C08·안전한 안내(SD3-14) 순서다. 자체 부합은 SD3-15로 별도 수행한다.

하나의 `OK`·hash·도구 성공은 다음 관문의 권한을 발급하지 않는다. 환경 증거와 현재성 확인은 모든 신규 읽기·쓰기·재읽기·상태 조회 직전에 반복한다. 모르는 조건은 빈 허용이 아니며 `BLOCKED`는 내부 진행 표시다. C08 오류는 계약의 code를 사용한다. 내용 오류 DATA_INVALID/CONTENT_MISMATCH, 정책 POLICY_UNVERIFIED/POLICY_STALE, 권한 PERMISSION_DENIED, 지원 DEPENDENCY_UNQUALIFIED, 한도 RESOURCE_LIMIT, 승인 APPROVAL_UNVERIFIED/APPROVAL_PROFILE_UNQUALIFIED, 안전 SAFETY_BLOCKED를 구별한다. 원격 효과 불명은 OUTCOME_UNKNOWN, 충돌 관측은 CONFLICT와 REMOTE_CONFLICT를 연결한다. 차단 해소는 새 증거로 해당 관문부터 재검사하며 시간 경과나 재시작으로 해제하지 않는다.

## 설계 해법

<a id="sd3-01"></a>
### SD3-01 — 실제 환경·도구·유한 실행 프로필 적격화

근거: NFR2.2, NFR8.2, NFR11.1~NFR11.2; TD3-01/08/09; WF3.01; BR1.1, BR5.3~BR5.5; C02, Common.Limits, CR01/10. 담당: U3 환경 검증자, 실제 연결 소유자. 권한 밖 기능을 새 PC/서버로 보충하지 않는다.

환경 검증자는 합성 자료와 이미 허용된 계정 범위에서 계정 별칭·요금제·웹/모바일·클라이언트/도구 이름·버전·관측 시점을 묶고, 읽기/JSON 생성/쓰기/전체 재읽기/승인 근거 전달/지속 조회를 각각 `미검증`, `미지원`, `증거 확보`로 기록한다. 한 환경의 성공은 다른 환경으로 전파하지 않는다. 공개 설명·합성 구조 성공은 실제 capability 증거가 아니다. 이 작업에서는 계정 검증을 실행하지 않는다.

적격 기록은 도구 자체가 반환한 관찰 가능한 검사 결과의 출처·버전·검사 범위·대상 전체 digest·실패 시 호출 중단 방법을 포함해야 한다. SD3-04의 엄격 parse/Schema/JCS/SHA-256과 SD3-07의 Decimal/tzdb를 실제 허용 도구가 결정적으로 수행할 수 있는지 확인한다. 모델이 hash를 말하거나 프롬프트에 중단을 적은 것만으로 도구 차단 강제력이 생기지 않는다. 도구가 필수 검사를 강제·입증하지 못하면 관련 외부 요청을 보류하고 대화/검사 명세만 제공한다. 신규 실행 환경·검증 서버·MCP·PC 실행 권한을 발명하지 않는다.

| 프로필 필수 항목 | 선정·적격화 절차 | 미확보 결과 |
|---|---|---|
| 연결/개별 요청/총 경과시간 | Common.Limits의 connectTimeoutMs/requestTimeoutMs/maxElapsedMs를 양의 유한 정수로 기입할 실제 도구 설정·강제/중단 수단을 확보하고 경계/초과 합성 호출로 확인. 연결≤요청≤총 경과를 만족하는 프로필만 채택 | 수치·실제 강제력 중 하나라도 없으면 신규 요청 보류 |
| 시도/호출 예산 | attemptLimit/requestBudget 및 같은 의도의 기간 예산·잔여량 확인 수단, 중단/재개 간 누적 방식·신뢰 시간원을 기록 | 누적/시계 복원 불명은 새 효과 보류 |
| bytes/깊이 | maxInputBytes/maxOutputBytes와 별도 로컬 검사 설정의 최대 깊이를 명시. 본문·내부 JSON·재읽기·오류·생성 출력까지 실제 제한되는지 확인. 깊이는 Common.Limits에 새 wire 필드로 추가하지 않음 | 전체 bytes를 얻지 못하거나 잘림/초과 중단이 불가하면 검증/전달 보류 |
| 백오프/지터 | 양의 유한 baseDelay/capDelay와 지터 지원/관측 수단을 프로필에 기입. k번째 대기는 min(capDelay, baseDelay×2^k)에 대한 0~상한 지터로 계산하고 Retry-After가 있으면 그보다 일찍 재호출하지 않음 | 지터·대기·총 한도를 강제할 경로 미확보는 자동 재시도 보류 |
| 결정적 검사/현재성 결합 | 고정 registry/검사 버전, 정책·승인 출처와 확인 시점/철회 규약, 대상 객체 고정 읽기/결과 추적 기능을 환경별로 적격화 | 지원·정책·승인 관문 중 미해소 항목을 명시하고 관련 기능 보류 |

실제 값은 현재 도구/계정 바인딩이 없으므로 미선정이다. 위 표는 선택 가능한 값의 조건과 합격 절차이며 예시 숫자·U2 systemd/SQLite/암호화 자격자료·RSS/p95·시간/bytes/depth/큐 수치를 U3 보장으로 전용하지 않는다. 최대한도에 딱 맞는 자료와 1단위 초과·미설정·미적격·소진을 각각 검사해, 초과/불명에서 새 호출이 발생하지 않아야 적격이다. 수치가 정해지기 전 관련 기능은 활성화되지 않는다.

대안: 플랫폼 자체의 입증 가능한 결정적 검사·제한 기능이 있으면 재사용하고, 이미 허용된 도구 경로가 같은 증거를 제공하면 그 경로를 평가한다. 어느 쪽도 입증하지 못하면 보류한다. 프롬프트만으로 강제·검증을 보장하는 대안은 채택하지 않는다. 장점은 불명 효과를 줄이는 것이며 비용은 지원 환경에서도 필요한 증거가 없으면 전송하지 못한다는 점이다. 시험/증거: B3-03/07/11, U3-06/28~32/36의 적격 기록과 실제 도구 관측은 후속 인수 대상이다.

<a id="sd3-02"></a>
### SD3-02 — 원 정책·실제 권한과 전 경로 공개 집합 관문

근거: NFR2.1, NFR3.1~NFR3.2, NFR4.1; TD3-03/04; WF3.03/11; BR2.1, BR2.4~BR2.5; C04/CR07. 담당: 원 정책 U2 DataAccessPolicy, 요청 직전 대조 U3/연결 소유자.

입력은 신뢰된 연결 설정에서 구한 실제 저장소·최종 독자 경로, 같은 주체의 원 정책/현재 개정·철회 결과와 전체 C04 digest다. 외부 JSON의 경로 목록·ACTIVE·verificationRecordRef는 증거가 아니다. SD3-01 적격 경로에서 매 요청 직전 실제 계정/비공개·공유 범위·목적·대상과 `(service,purpose,targetAlias)` 유일 grant를 대조한다. 중복 튜플은 합치지 않는다. 검사 시점 이후 철회/대상 변경을 발견하면 남은 전송을 중단하고 이미 시작한 효과의 관측/미확인을 보존한다. 원 정책을 확인할 경로 자체가 미해소이면 그 확인을 성공했다고 합성하거나 보호 자료를 먼저 읽지 않는다.

ANALYSIS에서는 각 실제 경로 grant의 분석용 9개 이름 `analysis.metadata`, `summary.period`, `activity.date`, `activity.sport`, `activity.distance`, `activity.duration`, `activity.intensity`, `activity.heartRate`, `summary.totals`만 추려 ASCII 정렬한 집합과 projection의 집합을 정확히 대조한다. 모든 경로에서 동일해야 한다. 최소 네 항목 analysis.metadata/summary.period/activity.date/activity.sport 각각의 명시 허용도 검사한다. 더 넓음/좁음/누락 모두 전체 신규 전송 PERMISSION_DENIED다. 교집합이나 자동 정책 변경은 없다. 명시 정책 변경 시 원 소유자가 만든 새 정책 digest·투영·snapshotId/digest로 다시 시작한다.

C05~C08도 goal.target/goal.availability/plan.sessions/plan.explanation/workflow.status의 해당 목적·대상 업무 묶음과 필수 메타데이터 허용을 검사하며 C03 동의로 대신하지 않는다. 미허용 필드를 잘라 같은 승인으로 보내지 않는다. 직접/수동, 분석 읽기/저장/상태 조회 모두 같은 관문을 통과한다. 결과는 요청 가능 범위 또는 정책/권한 보류와 경로별 차이만 안내한다. 원 정책 현재성/철회·ConsumerBinding 개정 식별/실제 ChatGPT serviceName 바인딩은 여전히 미해소다. 시험: U3-12~16/31/36·B3-02/07·U1 S01~S05/S17~S18/S21~S23에서 잘못 허용 0건.

<a id="sd3-03"></a>
### SD3-03 — 불신 입력과 최소 출력 경계

근거: NFR1.1~NFR1.2, NFR4.1; TD3-06/09; WF3.11; BR2.6; CR01/06/07/12. 담당: U3 작성/안내, 비밀 보호 구현은 각 소유 단위.

입력의 파일명·본문 설명·모델 결과·C08 suggestedAction·profileId·extension은 자료다. 임의 URL 추적·검증기/키 등록·PC/셸 실행·다른 계정/대상·철회 무시 지시를 권한으로 승격하지 않는다. 신뢰된 설정/고정 계약의 허용 행위만 검사 후보로 만들고 필수/권한 미지 필드는 SD3-04에서 거절한다. 모델 내부 판단이 외부 도구의 실제 권한을 제한한다는 보장은 하지 않는다. 그 권한/요청 통제 증거도 SD3-01의 필수조건이다.

대화·Markdown·전체 JSON/근거/자유 서술/extension·직접 저장/수동 후보·오류/진단 각각에서 인증정보·토큰·보호 보관 참조·직접 식별자·미등록 GPS/FIT/수면/HRV/통증이 포함되는지 검사한다. C03에는 자유 extension 자료를 추가하지 않는다. 비밀 의심을 안전하게 분리하지 못하면 원문을 echo하지 않고 전송을 보류한다. 안전한 수정으로 승인 내용이 바뀌면 SD3-09의 새 버전/새 승인으로 돌아간다. 별도 동의만으로 미등록 민감 필드를 만들지 않는다.

오류 출력은 고정 한국어 안내와 code/fieldPath/workRef/observedAt/조치로 제한하고 원 요청·헤더·토큰·원천 수치를 복사하지 않는다. 합성 음성 표식도 출력/로그/보고/스크린샷에 남기지 않는다. 시험 증거는 사례 ID·검사 표면/필드 경로·검사 건수·위반 건수와 판정만 남긴다. B3-01의 모든 표면과 지시 위치, U3-15/36을 각각 검사해 누출·실행/권한 확대 0건을 목표로 한다. 자연어 전체 비밀 탐지나 모든 공격 차단 보증은 아니다.

<a id="sd3-04"></a>
### SD3-04 — 고정 명세와 결정적 전체 내용 검증

근거: NFR5.1, NFR5.2; TD3-02/09; WF3.01/03/07; BR2.1~BR2.2, BR5.5; Common/C01/C02, CR01~03. 담당: U1 명세/부합 기준, U3 적격 도구 대조. 모델 hash 자칭이나 일반 JSON 직렬화만으로 JCS 합격을 만들지 않는다.

1. SD3-01/02 후 허용 고정 객체의 MIME/전체 입력 bytes·출력 bytes·깊이·시간/횟수 한도를 확인한다. 일부만 읽거나 잘린 경우 전체 검증을 보류한다.
2. 실제 도구의 엄격 UTF-8 디코더/중복키 거절 파서로 단일 루트 객체를 읽는다. 단일 선두 BOM과 바깥 공백/CRLF만 허용하고 문자열의 한글·인용·줄바꿈·이모지·코드 포인트는 보존한다. 잘못된 UTF-8·복수 BOM·중복키·잘림·후행 문서·NaN/Infinity·비객체는 DATA_INVALID다.
3. 신뢰된 고정 설치/배포 출처의 Common/C01~C08 1.0.0 registry를 선택한다. C01/C02 bootstrap도 고정하고 release의 C03~C08 각 등록 유일성·필수 계약·실제 schema digest/fixturesDigest를 대조한다. 같은 registry의 등록 C03 Detail fragment만 해석한다. 원격 $ref·미지원 버전·필수/권한 미지 필드·등록 규칙 밖 extension은 거절한다.
4. Draft 2020-12 구조 검사와 CR 교차 필드 의미 검사를 분리한다. 비권한 `extensions.x_*` 문자열/null도 권한/행동에 쓰지 않으며 허용된 경우 전체 내용에 포함한다. 권한/민감성 검사는 Schema 통과와 별개다.
5. 실제 적격 JCS 구현으로 대상 payload 전체를 정규화한 UTF-8 bytes에 SHA-256을 적용하고 `sha256:`+소문자 64자리와 ArtifactRef/기대 digest를 대조한다. 설명·가정·extension·시간/정책·대상 필드도 제외하지 않는다. C06·Markdown·파일명/헤더/수정 시각은 C05 안에 섞지 않고 각자의 참조로 연결한다.
6. 구조/의미/내용 동일성의 결과를 검사 도구·버전·명세/fixtures digest·대상 digest·시각·항목별 판정에 연결한다. 모델이 반환한 VERIFIED나 외부 VerificationResult는 이 결과를 대신하지 않는다. 일반 JCS Unicode/수치·정밀 Decimal 경계 적격성이 없으면 전체 검증 완료와 외부 전달을 보류한다.

불투명 ID는 1024자 경계까지 문자열 그대로 비교한다. 선행 0·대소문자·Unicode 정규화·숫자화를 하지 않고 초과는 거절/원본 참조 보존한다. 같은 이름 다른 ID는 별개, 개명/이동 같은 ID는 동일 객체 참조다. 원격 versionRef와 앱 versionId는 분리한다. 증거: B3-03/08·U3-10/18/25·U1 V/N/B/T. 현재는 도구/라이브러리 이름·버전 미선정이며 설치/신규 제품 추천을 수행하지 않는다.

### SD3-05 — 분석 조각·상태·파생 지표의 완전성 대조

근거: NFR3.2, NFR4.1, NFR7.1; TD3-03; WF3.03; BR2.2~BR2.5; C03/C04/CR03/07. 담당: U3 자료 검토, 원천 completeness 생산은 U2 AnalysisPublication.

SD3-02/04를 통과한 C03 manifest에서 INLINE은 expectedPartCount=0/detailArtifacts=[]/expectedActivityCount=activities 길이를 검사한다. PARTITIONED는 activities가 비어 있고 N≥1, N개 descriptor·0..N−1 유일/오름차순 index, 고정 저장소/객체/버전 참조 중복 없음, descriptor별 양의 activityCount와 합계 일치를 요구한다. 등록 Detail만 읽고 하위 탐색·순환/임의 URL은 거절한다.

각 Detail의 snapshotId/sourceSnapshotRef/subjectRef/projection/rootPeriod/partCount/digest·descriptor period/activityCount를 루트와 대조한다. 상세 기간은 루트 안에 있고 시간대가 같으며 실제 운동의 현지 일자가 시작 포함·끝 제외 범위 안이어야 한다. 조각 기간 겹침은 허용하며 기간 합집합을 수집완료로 해석하지 않는다. 각 조각 및 연결 결과의 `(UTC 순간, activityId Unicode 코드 포인트)` 정렬·전체 activityId 유일성과 sourceRevision 중복을 검사한다. 같은 ID 반복도 자동 무시·합산하지 않는다.

읽기/참조/버전/해시 확인 누락은 해당 조각을 제외하고 SOURCE_INCOMPLETE/effective PARTIAL·실패 조각/기간을 남긴다. 구조/계보/index/개수/중복/합계 오류는 DATA_INVALID로 스냅샷 근거 채택을 보류한다. 원천 COMPLETE/PARTIAL/EMPTY/NEVER_COLLECTED는 덮어쓰지 않는다. EMPTY는 수집 성공·INLINE 정상 0건·빈 요약/누락 없음, NEVER_COLLECTED는 sourceCollectedAt=null·INLINE 0건·missingPeriods=[period]다. 원천 PARTIAL은 전부 읽어도 COMPLETE로 올리지 않는다. 생성/수집/게시 시각·마지막 성공·오래됨/미동기화·미포함 기간은 별도 안내한다.

미허용 metrics 슬롯은 항상 withheld+quantity/sourceRef/calculationBasis=null이다. 허용 지표의 실제 상태만 유지한다. pace/speed는 intensity와 distance/duration 모두 허용할 때만 공개하며 심박은 별도 허용이다. summary.totals 미허용은 빈 summaryBySport, 허용 시 종목 유일성/activityCount·허용 거리 m/시간 s의 정확한 Decimal 합계를 모든 Detail 도착 후 대조한다. 비공개 요약도 withheld, 공개 입력의 합산 상태는 missing 우선→not_collected→not_applicable 제외(전부면 같은 상태)→수치 중 estimated 있으면 estimated→나머지 computed다. 분모0/withheld/미수집을 실제0으로 바꾸지 않는다. 자유 설명·계산 근거/summary로 숨긴 값의 역산/유출도 SD3-03에서 차단한다.

출력은 실제 사용 가능한 자료 집합·원천/유효 완전성·실패/누락 범위다. 전체 Detail 대조 전 루트 합계를 검증 완료로 안내하지 않는다. U3-07~17·B3-02/04·U1 S01~S23으로 검사하며 정밀 계산/실제 원천 수집의 적격성은 별도 미해소다.

### SD3-06 — 목표 개정과 근거 종류 고정

근거: NFR5.3, NFR8.1, NFR9.1; TD3-03/07; WF3.02~04; BR1.2~BR1.6, BR2.3, BR3.1, BR3.4. 담당: U3 CoachingWorkflow.

같은 사용자의 확인 입력·출처/시각·goalRevision을 대조하여 목표일·가능 시간·빈도를 재사용하고 부족한 필드만 확인한다. 최신 진술과 과거 입력이 상충/오래되면 해당 값·시각·근거를 제시하고 자동 승자를 고르지 않는다. 목표일 모름/가능 시간 없음은 미정·INCOMPLETE로 유지하며 목표일/빈도를 만들지 않는다. 수행 목표의 nullable 거리/시간은 허용해도 objective·목표일·실행 가능한 시간/빈도 필수 확인은 면제하지 않는다. 고정 운동/제약의 확인한 없음과 미확인은 구별한다.

음수 거리·불가능 날짜·from>to는 해당 필드 오류와 전체 C05 보류다. 정확한 개정 요약을 확인한 후에만 다음 단계로 진행한다. 목표 변경은 새 goalRevision/요약 확인이며 이전 확인을 새 내용에 재사용하지 않는다. 목표 확인은 게시 승인이 아니다. 중단 시 완료/미정 필드와 개정 참조를 SD3-13으로 넘긴다.

계획 근거는 실제 읽은 자료/기간/버전·진술·관측·결정적 계산·추정을 구분해 고정한다. 허용 기록 읽기 실패라면 Garmin 기반이라고 말하지 않으며 진술/추정 대안과 한계를 제시한다. 빈 기록/withheld·분모0을 능력/성과0으로 바꾸거나 측정 심박·달성 확률을 발명하지 않는다. 검사 증거는 필드별 출처 연결과 안내 대조(U3-01~05/08/17/21·B3-04/10)다. 자연어 품질/실제 의학 안전 보증은 없다.

### SD3-07 — 완전 계획·정밀 양·시간대 일괄 검사

근거: NFR5.3, NFR6.1~NFR6.2, NFR9.3; TD3-02/07/09; WF3.04~05; BR1.4, BR3.2~BR3.3, BR3.6~BR3.7; CR04~05. 담당: U3 계획 검증, U1 규범, 실제 tzdb/수치 적격 검증자.

입력은 확인한 목표 개정·전체 C05·timingPolicy·정책 digest·고정 운동/제약이다. 시작 포함·끝 제외·목표일 포함 여부·부분 주까지의 주차 목표/유일 주차 시작·세션 1개 이상·매일의 세션/휴식·sessionId/sessionVersionId 유일성을 전체 검사한다. 기간 밖·중복·필수값 누락·0시간·음수 거리·혼합 버전·잘림은 DATA_INVALID로 전체 보류한다. 유효 세션만 추려 보내지 않는다. 실제 완료 운동 참조/이전 완전본은 보존한다.

시간 검증은 원 오프셋과 UTC 순간을 둘 다 보존하며 수집/생성/게시 시각을 구분한다. 실제 IANA/tzdbVersion과 승인 timingPolicy의 timezone/defaultLocalTime/calendarAlias를 대조한다. 세션 localTime이 있으면 우선, null이면 해당 기본 시각으로 단일 해석한다. DST 중복/누락은 임의 오프셋 선택·자동 이동 없이 확인 전 보류한다. 예상시간은 경과시간이며 자정 넘김에도 종료/가능 시간·고정 운동·휴식 겹침을 검사한다. 자정/월말/윤일/연말과 같은 UTC·다른 오프셋 경계도 검사한다. 실제 Calendar 결과를 이 계산으로 자칭하지 않는다.

Decimal은 Quantity 십진 문자열을 정확히 읽어 같은 단위의 합계/비교를 재현해야 한다. 이진 부동소수 오차·조용한 반올림은 채택하지 않는다. 합계·강도 상하한·준비/본/정리와 구조화 expectedDuration/거리·설명 총량을 대조한다. 반복 소수/정밀도·반올림 기준이 미정이면 임의 결과를 확정하지 않고 해당 정량 해석/전달을 보류한다. 적격 도구 검증에는 정확한 덧셈/비교와 반복 소수·Unicode/JCS 수치 경계의 별도 결과가 필요하다.

강도는 heart_rate=bpm, pace=s/km, speed=m/s, rpe=rpe+유효 scaleRef, qualitative은 수치/단위/척도 null과 수행 설명을 요구한다. lower≤upper·척도 범위와 출처를 확인하며 단위를 섞거나 정성→수치/미측정→측정으로 바꾸지 않는다. 불명은 오류/정성 후보와 SD3-08의 안전 보류다. 고정 수영/러닝 겹침·휴식 충돌은 대안/확인을 제시하고 고정 운동을 옮기지 않는다. 시험: U3-04/18~21/23/25/26·B3-05/08. 기존 entities의 BR3.5 강도 참조와 규범 BR3.6 불일치는 SD3-15의 미해소 위험으로 유지한다.

### SD3-08 — 근거·안전 경고와 평가 실패 예외의 경계

### SD3-09 — 불투명 계보와 전체 내용 변경의 새 승인 대상화

근거: NFR5.2~NFR5.3, NFR10.3; TD3-02/04/05; WF3.05/08; BR4.2~BR4.6; CR02/09. 담당: U3 버전 작성, U2의 현재 확정 계보 판단은 독립 소유.

증거는 원/새/부모/원격 ref와 새 전체 digest의 분리·차이표·원 선언 보존이다. U3-05/25~27/32·B3-08/09에서 불투명 ID의 선행0/대소문자/Unicode·1024자 경계, 같은 이름 다른 ID/개명 같은 ID까지 대조한다. Drive 동시성·ConsumerBinding 개정 식별 부족은 실제 증거로 해소되기 전 미해소다.

### SD3-10 — 정확한 승인 의사와 불신 선언의 단일 행위 결합

근거: NFR10.1, NFR5.2; TD3-04; WF3.06; BR1.6, BR4.1~BR4.2; C06/CR06/09. 담당: U3 의사 수집·선언, 적격 독립 승인 검증/ApprovalProof는 U2 PlanAdmission.

### SD3-11 — 처분의 미래 영향과 REPLACE 두 범위 분리

근거: NFR10.2, NFR5.3; TD3-04; WF3.10; BR4.4, BR6.1~BR6.3; C07/CR06/11. 담당: U3 요청/영향 설명, U2 PlanAdmission/CalendarDelivery 현재 실행 판단.

입력은 WITHDRAW/REPLACE/CANCEL_PUBLICATION과 정확한 원 plan/version/digest·현재 연결·기준 시각·대상 세션이다. ALL_FUTURE는 대상 계획 미래 전체와 빈 sessionIds, SELECTED_FUTURE는 해당 계획 미래의 유일 세션 1개 이상을 검사한다. 과거/완료/타 계획/타 사용자 일정은 제외하고 혼합·대상/미래 판별 불명은 보류한다. 이름만으로 이벤트를 찾아 소유/삭제하지 않는다.

C07 전체 digest·정책에 단일 DISPOSITION 행위를 연결한다. WITHDRAW→WITHDRAW_PLAN, REPLACE→REPLACE_PLAN, CANCEL_PUBLICATION→CANCEL_PUBLICATION이다. REPLACE는 새 완전 C05의 정확한 ArtifactRef와 새 PUBLISH_PLAN 범위를 별도로 요구한다. 어느 한쪽 누락도 보류하며 하나의 의사로 두 근거를 임의 합성하지 않는다. 그 발급 가능성은 적격 프로필의 실제 검증 조건이다. 나머지 두 처분은 replacementPlan=null이다.

SD3-04/09/10/12를 통과한 STORE는 요청 전달만 의미한다. U2는 처리 시점의 현재 승인/계보·소유 연결·미래 여부를 재검사하므로 요청 당시 미래였어도 효과를 강제하지 않는다. 실제 운동/기존 승인본 보존, 실제 취소/교체는 SD3-14의 신뢰된 C08로만 설명한다. 시험 U3-26/33~35·B3-09/10은 각 처분·범위·누락 방향을 따로 대조한다.

### SD3-12 — 직접·수동 동일 조건과 자료별 실제 STORE 확인

근거: NFR2.1~NFR2.2, NFR5.4, NFR10.3; TD3-05/06; WF3.07; BR5.1~BR5.6, BR4.6; CR02/10/12. 담당: U3 STORE 관측/PlanTransferReceipt, 실제 Drive 권한·지원 검증은 연결 소유자.

SD3-01~11의 해당 관문을 모두 충족한 정확한 전달 의도에 workId·고정 대상 별칭·자료별 C05/C06/C07 전체 digest/앱 버전·기대 원격 참조·마지막 완료를 연결한다. 버전별 새 일반 UTF-8 JSON 객체이며 Markdown/Docs/Sheets 표시값은 판정 기준이 아니다. 직접 쓰기 미지원일 때 허용 수동 업로드 후보를 제시할 수 있어도 동일 정책/승인/전체 검증·실제 재읽기 증거 없이는 전달을 진행하지 않는다. 사용자 복사/편집으로 내용 변경 시 SD3-09/10으로 돌아간다.

효과 전에 원 의도·정확한 대상/기대 내용의 복원 가능성을 확인한다. 저장 응답/fileId/사용자 보고는 관찰일 뿐 성공이 아니다. 각 자료마다 다음 순서를 실제 적격 도구로 수행한다.

1. metadata-before: 허용 storeAlias/objectId·실제 위치/계정·비공개/공유 권한·JSON 형식·고정 remote versionRef를 관측한다.
2. 그 정확한 객체/버전의 blob 전체를 읽어 SD3-04로 엄격 parse/구조/전체 JCS digest·앱 versionId·C05/C06/C07 대상/정책 결합을 대조한다. 요약/검색 snippet·일부 페이지는 전체 재읽기가 아니다.
3. metadata-after: 같은 객체/위치/권한/remote versionRef가 안정적인지 확인한다. 버전 고정 읽기·변경 탐지 자체를 증명하지 못하면 성공을 내지 않는다. 앱 버전과 원격 버전을 혼용하지 않는다.

| 자료별 관측 | 결과와 복구 |
|---|---|
| 세 단계 모두 실제 확인·내용 동일·현재 조건 적격 | 해당 자료 STORE SUCCESS, 대상 digest/workId/관측 및 마지막 성공 시각 연결 |

다중 파일 원자성/자동 rollback은 없다. 필요한 자료 모두 확인한 경우만 묶음 STORE SUCCESS이며 U2 RECEIVE/VALIDATE/EVALUATE/CALENDAR와 별개다. 성공 후 조회 불가/권한 변경은 과거 성공을 지우지 않고 현재 OUTCOME_UNKNOWN/BLOCKED 관측을 추가한다. 지속 보관 완료는 실제 지속 조회 증거의 범위에서만 안내한다. U3-28~32·B3-06/07/11로 metadata-before/blob/after 각각의 실패·변경과 직접/수동 조건을 검사한다. 실제 Drive 지원/동시성·지속 재읽기는 미검증이다.

### SD3-13 — 재개 시 재적격화·미확인 효과 대조·유한 재시도

## Assumptions & Open Questions

새로운 범위/비용/정책 선택을 가정하지 않는다. 위 SD3-15의 미해소 항목은 실제 기능의 활성화/인수 차단 조건이다. NFR 문서 작성은 그 적격성을 발급하지 않는다. U3에 서버 SLA·가용성 백분율·RSS/p95·새 처리량·운영 대시보드를 만들지 않으며 관측은 현재 확인 범위·마지막 성공·미완료·이유·다음 조치로 한정한다.
