## 추가 질문 분석

별도의 사용자 판단이 필요한 신규 질문은 없다. 승인된 단위 배정과 계약을 그대로 적용하여 U1의 데이터 모델·규칙·검사 흐름·검증 연결을 구체화한다. 아래 요약은 신규 제품 범위나 외부 지원 사실을 확정하지 않는다.

U1은 배정된 30개 기능 요구사항의 명세 부분을 담당한다. U2/U3의 기존 31개 도메인 엔티티 소유권을 가져오지 않는다. U1에서 정의하는 명세 배포·계약 참조·합성 사례·적합성 판정의 모델은 제품의 승인·수집·게시 상태와 구별한다.

## Consolidated Summary Confirmation

- U1은 Common과 C01~C08의 공통 교환 표현·불변식·버전/호환 기준·합성 사례를 기능 설계한다. U2 소유 LLM 전용 스키마와 외부 어댑터에 역의존하지 않는다.
- 명세 배포·계약 참조·합성 사례·적합성 결과의 논리 모델을 정의하며, 기존 도메인 엔티티의 소유권과 제품의 실행 권한은 각 소유자에게 남긴다.
- 등록 명세 선택 → 엄격 파싱/구조 → 내용·참조·기간·수치·공유·상세의 의미 규칙 대조 → 근거별 판정의 흐름을 기술한다. 실제 입력의 바이트/깊이 한도 검사는 파싱 전부터 적용한다.
- 비공개 지표는 withheld로 구분한다. 실제 전송 경로 중 하나라도 분석용 허용 집합이 다르면 자동 교집합 생성 없이 신규 전송을 보류한다. 상세 누락은 PARTIAL, 중복/계보/집계 불일치는 채택 보류로 구분한다.
- 구조·의미 적합성과 사용자 승인 신뢰·정책 최신성·실제 전송/게시 성공을 별도 결과로 표현한다. U1 적합성만으로 관련 기능을 활성화하지 않는다.
- U1 배정 기능 요구사항 30개를 업무 규칙·흐름·합성 검증에 연결한다. 일반 JCS Unicode/수치 경계 등 아직 실행 증거가 없는 검증은 설계 대상으로 명시하고 기존 합성 검사 통과를 확장 해석하지 않는다.
- 확인 후 U1의 entities.md·rules.md·functional-spec.md·traceability.json을 작성할 입력으로 사용한다. 이번 작업 계획은 기능·비기능 설계까지이며 제품 구현·설치·외부 호출은 포함하지 않는다.
