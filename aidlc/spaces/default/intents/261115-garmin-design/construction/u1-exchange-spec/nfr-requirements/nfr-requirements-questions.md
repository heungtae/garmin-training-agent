# U1 공통 교환 명세 — 비기능 요구사항 확인

- 단위: U1 `u1-exchange-spec` (`spec`).
- 근거: [승인 기능 설계](../functional-design/functional-spec.md), [업무 규칙](../functional-design/rules.md), [상류 NFR](../../../inception/requirements-analysis/requirements.md), [공통 계약](../../../inception/contract-design/contract-summary.md), [단위별 NFR 배정](../../../inception/units-generation/unit-of-work-story-map.md).
- 이번 작업: NFR Requirements의 질문·요약 확인. 실제 제품 코드·검증기 구현·설치·외부 호출을 수행하지 않는다.

## 현재 적용 입력

리뷰 반영 요청과 승인된 최신 공통 계약/기능 설계에 따라 GTA-NUMERIC-1과 NUM-01~16을 상세 NFR에 반영한다. 계산 정밀도·반올림·동등성 규범은 확정됐고 실제 도구 부합은 미검증이다. 아래 문답/요약 확인은 이전 생성 시의 기록이며 답변을 새로 작성하거나 승인 범위를 확대하지 않는다. ConsumerBinding의 개정 식별 한계 등 나머지 수용 위험은 유지한다.

## 추가 질문 분석

별도의 사용자 판단이 필요한 신규 질문은 없다. U1은 독립 실행 서비스가 아닌 명세 단위이며, 승인된 Common/C01~C08·합성 자료·호환 기준에 대한 보안·무결성·시간/상태 표현·증거 추적을 상세 NFR로 구체화한다. 런타임의 응답 시간·처리량·메모리·재시도 수치와 운영 기술은 해당 실행 단위에서 결정한다.

U1 직접 배정은 NFR1·NFR2·NFR3·NFR4·NFR5·NFR6·NFR7·NFR10의 8개다. NFR8·NFR9·NFR11의 실제 재개·안전·외부 지원 검증은 U2/U3 책임이며, U1은 그 차단/증거 구분 계약을 완화하지 않는다.

기능 설계 승인 시 수용된 미해결 검토 항목은 해결됐다고 바꾸지 않는다. U1의 ConsumerBinding에는 소비자 구현/워크플로 개정 식별이 부족하다는 경미한 검토 항목이 남아 있다. 해당 개정별 부합 증거의 한계는 재현성/호환 설명에 명시하고, 이 단계가 기존 모델을 수정한 것으로 표현하지 않는다.

## NFR 범주와 측정 기준

| 범주 | U1 적용 | 요구사항 작성 기준·측정 범위 |
|---|---|---|
| 보안·데이터 보호 | 적용 | U1 자료는 합성만 사용. 합성 비밀 표식·금지 민감 자료가 허용되지 않은 생성물/출력에 0건이어야 함. 구조 필터만으로 자유 서술의 민감성 완전 검증을 자칭하지 않음 |
| 권한·정책 | 적용 | 미확인/철회·잘못된 서비스/목적/대상·경로 불일치의 필수 음성 사례에서 허용 판정 0건. 실제 권한 검증 자체는 해당 소유자 책임 |
| 무결성·호환 | 적용 | 고정 U1 registry의 모든 등록 참조 해석·schema/fixture digest 대조와 필수 적합성 사례의 예상 판정 일치. 미지 버전·변조·중복/혼합 내용의 조용한 채택 0건 |
| 시간·값·상태 | 적용 | 필수 기간/시간대·누락/0/추정/withheld·분할·부분 결과 사례에서 모호한 성공/동일성 해석 0건. 실제 시간대 데이터/생리적 안전 적격성은 별도 |
| 추적·증거 | 적용 | 동일 고정 입력·검사 범위·명세/실행 프로필에 대한 기대/관찰·미실행/미해소를 구분하고 대응 NFR/규칙/사례를 추적. 소비자 개정 식별의 승인된 한계는 유지 |
| 성능·확장·가용성·운영 관측 | 별도 서비스 목표 비적용 | U1에 서버 응답 SLA·동시 사용자 수·가용성 SLO·운영 대시보드를 새로 부여하지 않는다. 파싱 자원 한도/미설정 보류는 규범에 유지하고 실제 값/성능은 소비 단위로 연결 |
| 규제·공개 배포 | 추가 조건 미지정 | 실제 개인정보/건강 자료를 U1 증거에 사용하지 않는다. 추가 법정 인증을 임의 적용하거나 준수 완료로 선언하지 않음. 현재 저장소 접근 정책과 사용자 배포 권한 범위를 따른다 |

측정의 0건/전수 일치 목표는 지정된 필수 합성/정합 시험의 합격 기준이며 모든 입력의 보안성이나 실제 외부 동의/승인 성공을 증명하지 않는다. 실제 비밀/건강 자료를 시험에 넣어 검증하지 않는다.

## 기술 결정의 범위

- 승인된 Markdown 설명·UTF-8 JSON 명세/합성 사례·JSON Schema Draft 2020-12·RFC 8785 JCS·SHA-256·고정 registry와 전체 내용 digest를 기술 기준으로 유지한다.
- U1의 소유 범위는 Common과 C01~C08·공통 사례다. U2 전용 LLM 스키마·외부 어댑터/SDK·U3 전용 자료·DB·실행 파일에 역의존하지 않는다.
- 새로운 앱 언어·프레임워크·제품 DB·상시 서버·클라우드를 U1에 선택하지 않는다. 구현 라이브러리/버전·한도·측정 장비는 실제 구현 담당의 검증 가능한 선택과 NFR Design으로 연결하며, 명세 표준 준수를 라이브러리 이름만으로 인정하지 않는다.
- 의미/구조 적합성·일반 JCS 경계·제한 Mermaid 검사·실제 외부 연동/안전의 증거 수준을 구분한다. 이 단계에서 미실행 검증을 완료로 바꾸지 않는다.

## Consolidated Summary Confirmation

- U1 직접 배정 NFR 8개를 상세 NFRx.y와 측정·합격 기준으로 연결하고 security-requirements.md·tech-stack-decisions.md·traceability.json을 작성할 입력으로 사용한다.
- 합성 자료만 사용하며 비밀/금지 필드 출력 0건, 필수 거절 사례의 잘못된 허용 0건을 시험 범위의 합격 기준으로 삼는다. 실제 동의·승인 검증을 명세 적합성으로 대신하지 않는다.
- 고정 명세·참조·전체 내용 digest·호환과 필수 적합성 사례의 판정 일치를 요구한다. 누락/0/추정/withheld·기간·부분 실패/미확인 상태의 구분과 증거 추적을 유지한다.
- 기능 설계에서 승인된 미해결 검토 항목은 기존 한계로 기록하고 수정 완료로 표시하지 않는다. 실제 승인·정책 최신성·외부 지원·안전 적격성 차단도 유지한다.
- U1 기술 기준은 기존 Markdown/UTF-8 JSON·JSON Schema 2020-12·JCS/SHA-256·고정 registry다. 소비자 구현이나 U2 전용 API/스키마에 역의존하지 않는다.
- U1에는 별도의 서버 성능·확장·가용성·운영 관측 목표를 추가하지 않는다. 실제 자원/시간/호출 한도와 운영 기술은 소비 단위에서 정의한다.
- 작성 결과는 비기능 요구사항과 기술 결정의 설계이며 코드·패키지 설치·실제 외부 호출·제품 인수 결과가 아니다.
