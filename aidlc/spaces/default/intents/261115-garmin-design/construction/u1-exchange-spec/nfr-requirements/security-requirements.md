## 책임·위협·측정 경계

보호 대상은 허용된 교환 자료의 기밀성, 전체 JSON 내용/버전의 무결성, 승인 대상/행위의 정확한 연결, 상태와 증거의 정직한 표현이다. 불신 문서·파일명·자유 서술·URL·외부 VERIFIED·LLM 지시는 자료다. 명세/검증기 선택, 실행 명령, 권한 부여를 지시할 수 없다. U1은 원 사용자 인증·비밀 저장소·정책/승인 발급·원격 효과를 소유하지 않는다. U1 합성 검사는 실제 승인·동의나 외부 지원을 발급하지 않는다.

검사는 Common과 C01~C08 및 U1 공통 합성 사례만 대상으로 한다. 실제 사용자·활동·건강·인증정보는 읽거나 시험에 사용하지 않는다. 비밀/민감 자료 거절을 시험할 때에는 명시한 합성 표식을 **음성 입력 자료에만** 둔다. 표식 탐지 대상인 출력은 허용 전송 후보, 정상 생성물, 오류/진단/요약 및 시험 결과 보고다. 선언된 음성 입력/기대값 정의를 출력 유출 건수와 혼동하지 않으며 보고에는 원문 표식 대신 사례 ID·경로·건수만 남긴다. 비밀값·보호 보관 위치/참조·직접 개인 식별자는 wire 자료에 싣지 않는다.

각 행의 목표는 고정한 필수 검사 집합에 적용한다. **필수 사례에서 비밀/금지 자료 출력 0건, 거절/보류해야 할 사례의 잘못된 허용 0건, 등록 참조/digest 및 기대 판정 전수 일치**가 합격 기준이다. 하나라도 위반하면 해당 요구행은 실패다. 미실행/도구 미적격은 합격 분모에서 제외해 100%로 보이지 않고 NOT_RUN/미해소로 보고한다. 무효 입력의 올바른 거절·외부 조건의 올바른 보류는 기대 일치이며 제품 SUCCESS가 아니다. 일부 정상 사례만 골라 전체 적합성을 주장하지 않는다.

U1 명세 작성/공통 사례 정의는 U1 담당, 이를 실행하는 소비자 부합 검사와 실제 I/O·원 정책·실행의 검증은 U2/U3 담당이다. 아래 행의 소유자는 이 구분을 구체화한다. 서버 SLA·처리량·가용성 SLO·대시보드는 U1에 부여하지 않는다. 파싱 한도 미설정 보류는 유지하며 실제 바이트·깊이·시간·호출·비용·하드웨어 값은 실행 단위의 NFR Design과 검증으로 연결한다.

## 필수 합성 검사와 증거 인계

필수 집합은 [기능 설계의 사례 계획](../functional-design/functional-spec.md)과 [원 계약의 합성 사례](../../../inception/contract-design/contract-summary.md)에서 가져온다. 기존 기대값을 바꾸지 않는다. 각 행에 명시한 권한/비밀/철회/자유 서술 변형은 승인된 규칙의 검사 조건이며 새로운 wire 필드/권한/제품 정책이 아니다.

| 집합 | 필수 ID·조건 | 판정/증거 경계 |
|---|---|---|
| 구조/교환 | V01~V08·V12~V17, N01~N25·N33~N34, B01~B02 | U1 43개 ID. expectedSchema와 expectedGate를 별도 대조. 정상 구조에도 승인/정책/읽기 재확인 차단이 남음 |
| 엄격 수신 | T01~T07 및 FD03의 잘못된 UTF-8/두 BOM/유한 바이트·깊이 경계·한도 없음 | 파싱 불가 원시 입력에 JSON JCS digest를 자칭하지 않음. 원시 입력 식별/프로필과 기대 거절을 기록 |
| 투영·분할 | S01~S23 | COMPLETE/PARTIAL/DATA_INVALID/PERMISSION_DENIED 기대를 층별 비교. 상세 해시 변경의 PARTIAL을 전체 JSON 대상 변조의 일반 CONTENT_MISMATCH와 혼동하지 않음 |
| 기능 설계 경계 | FD01~FD26 | 각 ID에 정의한 모든 하위 조건 포함. FD05 일반 JCS·FD08 정밀도·FD10 tzdb 등은 적격 도구/근거 전 미수행/차단 유지 |
| 보호·권한 변형 | 각 상세 행의 합성 비밀/금지 자료 주입, 불신 지시, 공개/불명 대상, 최소 필드 각각 누락, 다른 서비스/목적/대상, 동의 전/거부/철회/현재성 불명, 자유 서술 불명, C05~C08 동의 누락 | 변형은 원 fixture/치환/합성 환경/해당 BR/상세 NFR/기대 거절·보류를 식별해 기록. 실행 결과 보고는 표식 원문 없이 ID·경로·건수만 포함 |

U2 전용 V09~V11·N26~N32·B03 및 EVALUATION·LLM_REQUEST·LLM_RESPONSE 자료/검사는 U1 자체 검사의 의존이 아니다. 논리 사례 ID 하나에 여러 경계가 포함되므로 ID 수를 시험 assertion 수나 제품 커버리지로 표시하지 않는다. RELEASE를 제외한 U1 fixture 이름→전체 내용 11개만 fixturesDigest에 포함한다. RELEASE는 C01/C02의 별도 구조 사례로 사용한다.

후속 실행 증거는 고정 릴리스/실제 입력·치환 조건, BR/상세 NFR, 수행 scope, 도구/실행 프로필, 기대/관찰, 판정, 안전한 증거 참조 및 미해소 외부 차단을 함께 연결해야 한다. 이는 **검사 보고에 필요한 정보**이며 C01~C08이나 ConsumerBinding에 새 필드를 추가하는 결정이 아니다. 실행 프로필에 필요한 실제 도구/버전/한도를 확보하지 못하면 해당 범위는 미해소다. ConsumerBinding의 기존 속성만으로 소비자 구현/워크플로 개정을 충분히 고정하지 못하므로 개정별 완전한 재현성을 주장하지 않는다.
