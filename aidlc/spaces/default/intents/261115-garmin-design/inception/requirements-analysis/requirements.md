# Garmin Training Agent 상세 요구사항

- 작성일: 2026-11-17
- 대상: 초기 제품 P0 설계 입력. 구현·배포·실제 연동 검증 결과는 아니다.
- 식별자: 이 문서의 FR/NFR 식별자는 이후 설계·단위·검증에서 그대로 사용한다. 원문 ID도 근거 열에 보존한다.
- 우선순위: 아래 FR1~FR9와 하위 요구사항 및 NFR1~NFR11은 모두 P0다. 후속 P1/P2는 별도 표로 보존한다.

## 의도 분석

개인 Garmin 사용자가 운동 기록 수집·분석·목표 등록·러닝 계획 검토·명시적 승인·저장·일정 게시를 연결하고, 단계별 성공과 실패를 확인하도록 한다. 외부 장애에도 기존 운동 기록과 승인 계획을 보존한다. 사용자가 계획을 통제하고, 자료의 출처·최신성·누락·불확실성을 구별하도록 한다.

이번 작업은 문서 설계이며 제품 완료는 모든 적용 P0와 실제 사용 환경의 인수 검증 후 판정한다. 초안 생성, 사용자 승인, Drive 저장 성공, 프로그램 수신, LLM 평가, Calendar 게시 성공은 각각 다른 결과다.

## 확정 정책과 해석

| 항목 | 초기 정책 | 근거 |
|---|---|---|
| 실행 주기 | 수집·저장소 동기화 1시간, 승인 계획 확인 15분. 별도로 변경·비활성화 가능 | Q1 |
| 평가 실패 | 이미 사용자 승인·형식·안전 검증을 통과한 정확한 버전은 LLM 평가 실패 사실을 표시하고 게시 가능. 오류 결과나 조정안을 반영해 게시하는 것은 금지 | Q2, LLM-005 |
| 승인 신뢰 | 정확한 버전과 사용자의 명시적 승인 근거를 신뢰성 있게 검증하면 PC 추가 확인 없음. 파일의 approved 표기만으로 인정하지 않음. 검증 불가 시 보류 | Q3, CHP-008, CMD-009 |
| 새 버전 | 내용 변경 버전에는 새 승인이 필요. 미승인 제안·가상 결과는 적용하지 않음 | Q8, SRS 업무 규칙 |
| LLM 유형 | 원격 하나 이상 및 로컬/사설 하나 이상의 연결 유형을 OpenAI 호환 API로 설계. 구체 제공자·모델·최소 하드웨어는 계약 설계에서 호환성 확인 후 선정 | Q4, LLM-002 |
| 일정 | 시간대·기본 운동 시각 설정 후 게시. 세션별 시각 우선, 알림은 대상 캘린더 기본값. 사용자 수정 충돌은 보류·안내 | Q5 |
| 공유 | 운동 날짜·종목·거리·시간·강도 지표를 후보로 서비스별 범위 확인·허용 후 전송. GPS 원본·FIT·수면/HRV·통증 등은 기본 제외 및 별도 동의. 인증정보 전송 금지 | Q6 |
| 보존·삭제 | 첫 설정에서 보존 기간 명시. 미설정 시 자동 삭제 없음. 원격 수정·삭제를 로컬에 자동 전파하지 않음. 삭제·일정 취소 전 영향 범위 확인 | Q7 |
| 저장 형식 | Drive 형식은 실제 읽기·쓰기와 승인 검증을 비교해 계약 설계에서 결정 | Q8 |
| 범위 | 한 사용자·한 PC, 러닝 계획 우선. 다른 종목 수집·구분·기간 통계와 고정 운동·회복 고려 유지. P1/P2 자동 편입 없음 | SCP, Q8 |

Q2는 LLM-005의 오류 결과 반영 금지를 완화하지 않는다. LLM 결과를 쓰지 않는 기존 승인 버전의 게시 경로만 허용한다. 승인·형식·안전 검증 실패나 확인된 미해소 안전 경고는 평가 호출 실패와 구분하여 게시를 보류한다. 안전 기준의 구체 규칙·한계값은 해당 근거와 함께 기능 설계에서 정하며, 미검증 임계값을 의학적 안전 보장으로 표시하지 않는다.

## 기능 요구사항

각 행은 요구 동작과 합격/실패를 구분하는 수용 기준이다. 정상 조건과 오류/경계 조건을 함께 기술한다. 기능 묶음의 수용은 모든 하위 행 및 공통 경계 기준 충족을 요구한다.

### FR1 — 설치·예약 실행·CLI 운영

근거: INS-001~008, DEC-001~003, FEA, Q1. Rust·Ubuntu 24.04 이상에서 CLI만으로 초기 설정과 운영을 완료하고 로그아웃 중에도 등록한 작업을 실행할 수 있어야 한다.

| ID | 원문 | 요구사항 및 수용 기준 |
|---|---|---|
| FR1.1 | INS-001 | 설치·초기화·실행·제거를 제공한다. 초기 상태에서 설치·실행 절차가 성공하고, 지원 밖 환경·권한 부족은 원인과 조치를 표시한다. 제거는 등록 실행을 중단하며 보존 데이터 삭제와 구분해 영향 범위를 확인한다. |
| FR1.2 | INS-002 | Garmin 인증, 최초 수집 기간·범위, 저장 대상별 활성화, 두 실행 주기, 시간대를 설정한다. 필수값·기간·주기·시간대 오류는 해당 필드와 수정 방법을 표시하고 유효한 기존 설정을 훼손하지 않는다. 비밀값은 화면·설정 조회에서 노출하지 않는다. |
| FR1.3 | INS-003 | 설정 완료 후 별도 수동 명령 없이 정기 작업을 등록한다. 로그인·로그아웃 양쪽에서 등록 주기의 실행을 실측한다. 종료·절전 중 실행을 보장하지 않으며 복귀 후 FR1.7을 적용한다. |
| FR1.4 | INS-004 | 수집·동기화 기본 1시간과 계획 확인 기본 15분을 각각 조회·변경·중단·재개한다. 중단한 작업은 새 예약 실행을 시작하지 않으며 재개 결과와 유효 설정을 확인할 수 있다. 0·음수·지원 불가 주기는 거절하고 기존 주기를 보존한다. |
| FR1.5 | INS-005 | 즉시 동기화와 마지막 실행 시각·결과·다음 예정 실행을 제공한다. 최초 실행 전·비활성 상태는 실행 성공이나 예정 시각처럼 표시하지 않는다. 즉시 실행과 예약 실행이 겹쳐도 FR1.6을 만족한다. |
| FR1.6 | INS-006 | 같은 PC의 중복 실행이 데이터를 손상하거나 중복 게시하지 않는다. 동일 작업 두 개와 중단 후 재실행에서 한 번 실행한 것과 같은 최종 데이터·세션 수를 유지하고 대기·건너뜀·복구 상태를 표시한다. |
| FR1.7 | INS-007 | 종료·절전·오프라인 뒤 누락 가능 기간을 재검사한다. 마지막 확정 위치 이후 미수집·미처리 자료가 다시 처리되고, 성공하지 않은 기간을 완료로 넘기지 않는다. 빈 결과와 조회 실패를 구분한다. |
| FR1.8 | INS-008 | CLI로 설치·연결·실행·상태·복구·제거를 완료하고 한국어 안내를 제공한다. 실패는 대상·유형·사용자 조치를 텍스트와 종료 결과로 구별하며 비밀정보를 포함하지 않는다. 경로·도구·설정 누락은 해당 항목을 지정해 안내한다. |

### FR2 — Garmin 인증·운동 수집

근거: GAR-001~007·010~011, VAL-001. 공식 Personal API에서 실제 허용되는 종목·지표만 수집하고 수정·누락·미지원과 중복을 구분해야 한다.

| ID | 원문 | 요구사항 및 수용 기준 |
|---|---|---|
| FR2.1 | GAR-001 | 개인 인증을 안전하게 등록하고 연결 시험을 제공한다. 키 참조 이름은 GARMIN_API_KEY이며 인증 형식·필요 권한은 공식 계약 확인 후 정한다. 미설정·거절·만료는 성공과 구분하고 인증정보를 노출하지 않는다. |
| FR2.2 | GAR-002 | 허용된 운동 목록·상세를 주기적으로 수집한다. 여러 페이지와 마지막 빈 페이지까지 누락 없이 처리하며 일부 상세 실패는 해당 항목의 미완료로 남긴다. 목록 실패를 운동 0건으로 확정하지 않는다. |
| FR2.3 | GAR-003 | 최초 기간을 설정하고 이후 신규·수정 기록을 구분한다. 기간 경계·재개·늦게 도착한 수정에서 이전 데이터와 일관된 결과를 내고 출처의 수정 여부를 알 수 없으면 그 한계를 표시한다. |
| FR2.4 | GAR-004 | 동일 운동 반복 수신 시 단일 운동·단일 집계를 유지한다. 외부 ID는 대소문자·선행 0을 보존하는 불투명 식별자로 취급하고 이름·동일 날짜만으로 다른 운동을 합치지 않는다. |
| FR2.5 | GAR-005 | 원천의 수정이 확인되면 해당 운동과 영향받는 통계·보고서를 갱신한다. 갱신 실패 시 이전 유효 자료와 갱신 필요 상태를 보존하며 원격 수정·삭제 충돌에는 FR3.7을 적용한다. |
| FR2.6 | GAR-006 | 러닝·수영 등 제공되는 운동 유형과 유형별 지표를 구분해 수집한다. 미지원/알 수 없는 유형은 러닝으로 치환하지 않고 구분 상태를 남긴다. 수영·사이클 전용 계획은 후속이다. |
| FR2.7 | GAR-007 | 거리·시간·페이스/속도·심박 등 허용된 값의 단위·원천·수집 시각을 보존한다. 변환값은 계산 기준을 식별하고 단위 누락·비현실적 값·미지원 필드를 알려 정상 측정값과 혼합하지 않는다. |
| FR2.8 | GAR-010 | 인증 만료·호출 제한·부분 누락·통신 및 응답 오류를 구별하고 제한에 맞는 재시도와 사용자 조치를 제공한다. 한 항목 실패로 유효한 다른 운동을 버리지 않고 미완료 목록과 수집 완전성을 표시한다. |
| FR2.9 | GAR-011 | 미제공 값은 사실처럼 생성하지 않는다. 누락·미수집·해당 없음·실제 0·계산 추정이 종단 간 구분되며, 운동 미수집은 미운동으로 단정되지 않는다. |

### FR3 — 로컬 보존·GitHub/Drive 동기화

근거: STO-001~009, DEC-004, Q6~Q7. 로컬 유효 자료를 먼저 확정하고 대상별 독립 게시와 명시적 충돌 처리를 제공해야 한다.

| ID | 원문 | 요구사항 및 수용 기준 |
|---|---|---|
| FR3.1 | STO-001 | GitHub와 Drive를 각각 등록·인증·연결 시험한다. 한쪽 인증 실패는 다른 쪽 설정과 로컬 자료를 손상하지 않으며 실제 권한 시험 전 쓰기 지원을 확정하지 않는다. |
| FR3.2 | STO-002 | 둘 중 하나 또는 양쪽을 선택할 수 있다. 비활성 대상에 데이터를 보내지 않고 아무 대상도 유효하지 않으면 로컬 보존과 외부 미게시 상태를 명시한다. 목표·계획의 필수 Drive 전달 경로는 FR5.9·FR7과 별도로 충족해야 한다. |
| FR3.3 | STO-003 | 원본 또는 정규화 자료를 외부 게시 전 로컬에 안전하게 보존한다. 디스크 가득 참·읽기 전용·중단 시 이전 유효 자료를 보존하고 새 자료의 저장·게시 성공을 주장하지 않는다. |
| FR3.4 | STO-004 | 대상별 성공·실패·대기 상태를 확인한다. 양쪽 중 한쪽만 성공하면 부분 성공으로 보이며 전체 동기화 완료로 표시하지 않는다. |
| FR3.5 | STO-005 | 한 대상 실패가 다른 대상의 성공을 무효화하지 않는다. 실패 대상만 재시도할 수 있고 성공 대상을 되돌리거나 중복 생성하지 않는다. |

## 제약

- Rust 설치형 프로그램, Ubuntu 24.04 이상, CLI 운영과 로그아웃 중 예약 실행을 대상으로 한다. Rust 경험이 없는 사용자도 문서화한 절차를 따라 설치·상태·복구를 수행할 수 있어야 한다(FR1.8).
- 한 사용자·한 PC에서 자동 작업을 실행한다. 같은 PC 중복 작업과 Drive 클라이언트 동시 변경은 여전히 처리해야 한다.
- 초기 계획은 러닝 우선이다. 다른 종목의 수집·단위/통계 구분과 고정 운동·회복 고려는 유지한다.
- GitHub/Drive는 각각 또는 병행 선택할 수 있지만, 승인 목표·계획의 전달은 별도 필수 Drive 경로다. GitHub만 선택했다고 Drive 계획 전달 요구사항이 면제되지 않는다.
- ChatGPT↔Drive↔설치 프로그램의 비동기 경로를 기준으로 하며 로컬 직접 실행·상시 클라우드·Garmin MCP·AWS·Bedrock을 필수로 두지 않는다.
- 실제 Garmin 접근 권한 보유는 사용자 확인이다. API 인증 계약·지표·한도·갱신과 Google/GitHub/ChatGPT 읽기·쓰기 권한은 검증 전이다. 키 값이나 실제 건강 자료를 문서·로그에 남기지 않는다.
- 예산 상한·마감·추가 필수 기술은 지정되지 않았다. 유료 서비스 비용 조건은 사용 전 결정한다.
- 외부 제한으로 P0가 불가능하면 허용 대안을 검증하며, 대안도 미충족이면 보류하고 요청자에게 범위 결정을 받는다. 완료 조건을 임의 축소하지 않는다.

## 추적성과 완료 판정

[추적성 목록](traceability.json)은 이 문서가 정의한 모든 FR·하위 FR·NFR ID를 포함한다. 각 행의 원문 열은 초기 P0 94개(기능 83개·비기능 11개)를 보존하는 매핑이다. NFR-011은 진단과 실행 추적을 위해 NFR7·NFR10에 중복 연결한다. 설계·Unit·테스트 참조는 아직 미작성이며 다음 단계에서 같은 ID에 연결한다. 현재 문서의 매핑 수는 구현/테스트 커버리지나 외부 연동 성공률이 아니다.

제품 완료는 실제 Ubuntu 설치·로그아웃 실행, Garmin 실제 허용 자료 수집, 선택 저장소 실제 독립 동기화, 실제 지원 ChatGPT 환경의 분석·목표/계획 승인·검증 가능한 Drive 저장, 프로그램 수신/승인 검증, 원격 및 로컬/사설 LLM 실제 평가, Calendar 실제 게시·중복/충돌/복구 증거를 요구한다. 모든 적용 P0와 위 인수 조건이 충족되어야 하며 설계만으로 완료 처리하지 않는다.
