# 도메인 설계 결정 기록

- 작성일: 2026-11-17
- 근거: [상세 요구사항](../requirements-analysis/requirements.md), [도메인 질문·확인 요약](domain-design-questions.md), [컴포넌트 목록](components.md).
- 범위: 논리적 컴포넌트 경계·데이터 소유·상호작용. 요청자가 선택한 8개 책임을 구체화한 단계 승인용 설계다. 구현·배포 단위·API/파일 스키마·실제 외부 지원을 확정하지 않는다.

## ADR-001: 8개 책임 경계

### Context

FR1~FR9는 예약 실행, 측정 사실, 분석 산출물, 대화 작성, 승인 검증, 평가, 외부 게시를 연결한다. 한 사용자·한 PC라는 규모 제약과 승인·개인정보·대상별 실패 격리 요구(NFR1~5·NFR7~11)를 함께 충족해야 한다. Q1에서 8개·6개·4개 분해의 장단점과 가역성을 제시했고 요청자가 A안을 선택했다.

### Decision

OperationControl, DataAccessPolicy, ActivityCollection, AnalysisPublication, CoachingWorkflow, PlanAdmission, PlanEvaluation, CalendarDelivery로 논리적 책임을 분리한다. 목표·계획 작성과 수신 검증, LLM 평가와 Calendar 반영, 실행 설정과 공유 권한을 각각 구분한다. 도메인 경계는 같은 프로그램 내 모듈 또는 후속 배포 단위로 묶을 수 있으며 여기서는 배포 토폴로지를 선택하지 않는다.

### Consequences

- 작성본을 생산하는 기능이 그 결과를 신뢰 승인으로 스스로 승격시키지 않는다. 데이터 전송자는 서비스별 정책을 확인한다.
- 외부 서비스의 실패·실행 결과·업무 상태가 구별되어 단위 검증과 원인 추적을 구성할 수 있다.
- 8개 경계 사이의 입력·결과·오류 계약이 필요하고, 소유자 조정 없이 임의 분할/통합하면 상태 의미가 달라질 수 있다.
- 개인정보는 각 경계에서 필요한 최소 참조/자료만 사용한다. 컴포넌트 수가 많다는 이유로 추가 원격 서비스·공개 저장소·권한을 도입하지 않는다.

### Alternatives Rejected

- **6개 경계:** 운영/정책과 작성/검증을 각각 합친다. 연결 계약은 줄지만 동의 철회·승인 신뢰의 변경이 일반 실행 설정·대화 편집과 결합된다. 요청자는 분리 검토를 우선했다.
- **4개 경계:** 운영권한·수집분석게시·계획작성검증평가·Calendar로 묶는다. 목록은 간단하지만 원천 사실과 파생 자료, 작성·승인·평가가 넓은 변경/테스트 범위를 공유한다.
- 향후 통합은 가능하나 해당 소유자·호출·상태·요구사항 연결을 함께 재검토해야 한다. 지금의 분리는 추가 기능을 승인한 것이 아니다.

## ADR-002: 단일 소유자와 작성본·검증 스냅샷 분리

### Context

Garmin 원천 수정(FR2.5), 요약 갱신(FR4.8), 부분 계획/동시 변경 차단(FR6.12·FR7.7), 명시적 사용자 승인(FR5.8), 새 버전 새 승인(FR6.10), 완료 실제 운동 보호(FR6.11)가 필요하다. 외부 작성본을 가변 참조로만 보관하면 게시 시 사용한 정확한 내용을 재확인할 수 없다.

### Decision

각 엔티티는 components.md YAML의 소유자 한 곳에서 변경한다. 원천 운동은 ActivityCollection, 파생 요약은 AnalysisPublication, 목표/작성 버전/세션/승인 의사는 CoachingWorkflow가 소유한다. PlanAdmission은 수신 자료를 검사하고 별도의 ApprovalProof·AdmittedPlanSnapshot·AdmissionAssessment를 보존한다. 작성본과 검증 사본은 원 버전·내용 참조로 계보를 연결한다.

ApprovalDeclaration은 수신 전 신뢰를 보장하지 않는다. 검증 근거가 사용자·내용·허용 행위와 결합되어야 ApprovalProof로 보존한다. CalendarDelivery는 실제 게시 전에 현재 스냅샷의 적격성을 확인한다. 정확한 내용 결합·현재 버전 확인·승인 증명의 구체 수단은 Contract Design에서 선택하고 검증한다.

### Consequences

- 작성 이후 변경·부분 작성·구버전·다른 사용자/행위 승인을 동일 승인으로 처리하지 않는다. 변조 방지 구현이나 실제 사용자 확인 성공을 이 설계만으로 주장하지 않는다.
- 작성본과 검증 사본의 개인정보 복제가 생긴다. 공유 동의·보존·삭제 범위에 각각 포함하고 외부 삭제가 자동으로 로컬 삭제나 복구 성공을 의미하지 않도록 한다.
- 서로 다른 컴포넌트는 소유자의 계약을 통해 조회하거나 작업을 요청한다. 동일한 저장 기술을 선택하더라도 공동 가변 데이터 소유는 허용하지 않는다.
- 원격 사용자 수정은 충돌로 남기고, Garmin의 확인된 원천 수정과 구별한다. 계획 개정으로 실제 운동은 바꾸지 않는다.
- 실제 승인 검증을 신뢰성 있게 구성하지 못하면 자동 게시를 보류한다. 추가 PC 확인을 기본 정책으로 몰래 도입하지 않는다.

### Alternatives Rejected

- **공동 가변 계획 객체:** 작성·수신·평가·게시가 같은 내용을 갱신한다. 소유가 모호하고 예전 승인과 새 내용의 결합·동시 수정·완료 운동 덮어쓰기 위험이 커진다.
- **Drive 포인터만 저장:** 복제는 줄지만 원격 내용 변화/삭제 후 검증 당시 내용과 게시 근거를 재현하기 어렵다.
- **중앙 데이터 컴포넌트가 모든 엔티티 소유:** 물리 저장과 업무 소유를 결합해 모든 도메인 변경이 중앙 객체에 모인다. 각 책임의 불변식·실패 경계가 흐려진다.

## ADR-003: 비순환 호출과 저장 자료를 통한 비동기 경계

### Context

FR5.11은 ChatGPT의 로컬 직접 호출을 필수로 요구하지 않는다. 수집·동기화와 계획 확인 주기가 다르며 오프라인·부분 저장·중단 후 재개를 처리해야 한다(FR1.4·FR1.7, NFR8). 서로 결과를 되물으며 호출하는 구조는 중복 재처리와 실패 추적을 어렵게 한다.

### Decision

OperationControl이 설치 프로그램의 실행을 조정하고, 각 업무 소유자가 결과·오류·미완료 정보를 보존한다. 컴포넌트의 depends_on은 논리적 요청 또는 저장 자료의 비동기 소비를 나타내며 dependents와 대칭으로 기록한다. 호출 그래프는 비순환으로 한다.

CoachingWorkflow는 AnalysisPublication의 게시 자료와 사용자가 확인한 정책을 비동기로 이용한다. PlanAdmission은 CoachingWorkflow가 Drive에 남긴 자료를 비동기로 수신한다. 이는 로컬 프로그램 직접 호출이나 특정 ChatGPT 도구 지원을 확정하는 인터페이스가 아니다.

응답 반환과 상위 조정자가 다음 요청에 전달하는 근거는 역방향 호출이 아니다. 예를 들어 CalendarDelivery가 평가 결과를 PlanAdmission의 최종 판정 입력으로 전달하며, PlanAdmission이 PlanEvaluation을 다시 호출하지 않는다. 원 설정 소유자인 OperationControl은 시간대/기본 시각을 작업 입력으로 전달하므로 CalendarDelivery도 역호출하지 않는다.

### Consequences

- 데이터와 실행의 소유자가 명확하고, 저장소/LLM/Calendar 실패를 독립적으로 기록할 수 있다.
- 저장 자료 교환에는 스키마·정책/승인 최신성·완전성·대상 식별과 중복/충돌 계약이 필요하다. 이런 계약을 실제 지원 환경에서 검증하기 전 자동화 가능을 확정하지 않는다.
- 동의 철회나 정책 변경을 ChatGPT 환경에 전달하고 새 요청에 적용하는 방법도 Contract Design의 해소 조건이다. 최신 허용 범위를 신뢰할 수 없으면 관련 전송을 보류한다.
- 각 전송자는 권한·허용 필드를 검사하고 비밀 참조를 외부 자료에 포함하지 않는다. 별도 클라우드·중개 서버·공개 수신 주소를 이 결정으로 도입하지 않는다.
- sync/async는 논리적 상호작용 형태다. HTTP·공유 라이브러리·프로세스·큐 등 물리 구현과 수치 지연은 후속 단계에서 정한다.

### Alternatives Rejected

- **ChatGPT가 로컬 프로그램을 직접 호출하는 필수 경로:** 초기 연결 가정과 충돌하며 상시 가용성·추가 노출/인증을 요구한다.
- **모든 컴포넌트의 상호 호출:** 실행 결과 재귀·상태 역전·재시도 중복이 발생하기 쉽고 단일 소유 원칙을 약화한다.
- **중앙 이벤트 중개 기반을 선결정:** 지금 확인하지 않은 운영 의존성과 메시지 전달 보장 설계를 추가한다. 저장 자료 경계와 책임을 먼저 정하고 물리 메커니즘은 이후 비교한다.

## ADR-004: 검증·평가·게시 결과의 권한과 상태 분리

### Context

사용자는 요구사항 Q2에서 평가 실패를 알린 후 검증 통과 승인 버전을 게시할 수 있도록 선택했다. Q3은 정확한 버전과 승인 근거를 검증할 경우 추가 PC 확인을 요구하지 않으며, Q8은 새 버전에 새 승인을 요구한다. LLM-005의 오류 결과 자동 반영 금지와 Calendar 중복/충돌/복구(FR9.4~7)도 유지해야 한다.

### Decision

PlanAdmission이 완전성·승인·내용 동일성과 안전 근거를 검사해 스냅샷을 보존한다. 평가 입력으로 사용할 수 있는 스냅샷의 수신과 실제 게시 직전 최종 적격 판단은 구분한다. PlanEvaluation은 해당 버전의 평가 결과 또는 명시적 실패를 소유하고 승인·게시 상태를 변경하지 않는다.

CalendarDelivery가 같은 버전의 평가 근거를 PlanAdmission에 전달해 최종 판단을 받고, 현재 적격한 버전만 반영한다. **확인된 평가 호출 실패**는 기존 승인·형식·안전 검증을 통과한 변경 없는 버전에 한해 고지 후 게시할 수 있다. **내용이 달라짐, 승인 불명, 안전 검증 실패, 미해소 안전 경고, 오류 LLM 조정안**은 이 예외에 해당하지 않는다.

PublicationIntent·CalendarBinding·DeliveryAttempt·CalendarConflict는 CalendarDelivery가 소유한다. 게시·갱신·취소는 해당 세션과 원격 결과를 대조하고 사용자 수정 충돌/응답 유실은 확인 전 덮어쓰기나 새 객체 생성으로 해결하지 않는다. Drive 저장·승인·수신 성공과 Calendar 부분 성공/실패를 분리한다.

### Consequences

- LLM 응답은 승인 권한이 되지 않으며 오류 조정안·새 버전이 기존 승인을 상속하지 않는다.
- 게시 중단/실패에도 원 운동·계획·검증 근거가 유지되고 대상 세션만 복구할 수 있다.
- 최종 판단에 사용할 평가 상태/경고의 구조·판별과 승인/원격 변경 확인 시점은 Contract/Functional Design에서 구체화해야 한다. 안전 규칙의 근거·한계값도 기능 설계에서 제시해야 하며 의학적 안전을 보장하지 않는다.
- 외부 게시 직전 확인과 실제 쓰기 사이의 동시 변경, 원격 결과 불명, 재시도에 대한 계약/검증이 필요하다. 현 단계는 해당 경쟁 조건을 구현·해소한 증거가 아니다.
- 게시 이벤트에는 서비스별 허용된 세션 정보만 포함한다. 평가에 쓴 민감한 원천 자료나 인증정보를 이벤트/알림에 복제하지 않는다.

### Alternatives Rejected

- **평가 성공을 사용자 승인으로 사용:** 명시적 사용자 승인·정확한 내용 검증 요구를 충족하지 않는다.
- **평가 실패 시 항상 보류:** 요구사항 Q2에서 선택한 정책과 다르다. 승인·형식·안전 검증 실패의 보류는 별도로 유지한다.
- **작성 또는 승인 상태를 전체 게시 성공으로 사용:** 대상별 실패·세션 연결·사용자 수정·응답 유실을 표현할 수 없다.
- **CalendarDelivery가 검증/계획 내용을 직접 수정:** 새 버전 승인 요구와 단일 데이터 소유 경계를 위반한다.

## 미확정 사항과 전달

위 결정은 코드·DB·서버·프로토콜·배포를 선택하지 않는다. Drive 형식과 승인 신뢰 계약, 정책 교환 최신성, 서비스별 실제 권한, 데이터 스키마/검증 규칙, 안전 기준, 재시도·영속 저장·예약 실행 수단은 [컴포넌트 설계의 후속 조건](components.md) 및 승인된 상세 요구사항의 OPEN/VAL 항목에 연결한다. 조건이 충족되지 않으면 관련 자동화를 보류하며 범위를 임의로 줄이지 않는다.
