# Garmin Training Agent 착수 개요

## 목적과 대상

개인 Garmin 사용자의 운동 기록 수집·분석·훈련 계획·일정 관리를 연결해 수작업을 줄인다. 기록 정확성·계획 통제·개인정보 보호·연동 상태를 중시하며, 요청자가 범위와 우선순위를 최종 결정한다. 근거: [목적 정의](../intent-capture/intent-statement.md), [이해관계자](../intent-capture/stakeholder-map.md).

## 초기 제품과 이번 작업의 경계

[범위 정의](../scope-definition/scope-document.md)에 따라 P0를 초기 필수, P1/P2를 후속으로 둔다. 초기 계획은 러닝 우선이며 자동 동기화·게시는 사용자 한 명·PC 한 대를 대상으로 한다. 다른 종목의 수집·구분·통계와 러닝 계획에서 고정 운동·회복을 고려하는 요구사항은 유지한다. 상용 다중 사용자·과금·별도 모바일 앱은 초기 제외다. Garmin 시계 직접 게시는 권한 검증 전 제외한다.

이번 작업의 결과는 요구사항에 추적 가능한 설계다. 실제 제품 구현·배포·연동 성공 판정은 별도다. 초기 제품의 성공 기준은 수집→분석→명시적 계획 승인→저장→일정 게시 및 장애 시 기록·승인 계획 보존이다.

## 타당성과 제약

[타당성 평가](../feasibility/feasibility-assessment.md)는 조건부 설계 진행 가능으로 판단했다. Garmin 공식 API 접근 권한 보유는 사용자 확인이며 실제 호출·세부 권한은 미검증이다. ChatGPT·Google·GitHub의 환경별 읽기·쓰기와 프로그램 권한, Calendar 게시 및 로그아웃 실행도 미검증이다. [제약 목록](../feasibility/constraint-register.md)에 따라 Rust·Ubuntu 24.04 이상·로그아웃 중 자동 실행을 대상으로 하며, Rust 경험이 없는 사용자가 설치·운영할 수 있도록 설명해야 한다. 필수 AWS 서비스는 없다.

## 위험과 대응

핵심 위험은 외부 기능 미지원, 승인·저장·게시 혼동, 중복 처리, 정보 노출, 실행 누락, LLM 오류·비용이다. [RAID 기록](../feasibility/raid-log.md)의 미해소 상태와 해소 조건을 다음 단계로 넘긴다. 미검증 기능을 지원 확정으로 표시하지 않는다. 허용된 대안을 평가해도 P0를 충족하지 못하면 해당 경로를 보류하고 요청자에게 범위 결정을 받는다.

## 검토 순서와 가치 흐름

[우선순위 백로그](../scope-definition/intent-backlog.md)의 IB-01~08을 초기 설계 대상으로 삼는다. Garmin 접근·ChatGPT 저장·승인 신뢰성을 먼저 검토한 뒤 수집·보존→분석 자료→러닝 계획 검토·승인→Drive 수신·검증→평가·일정 게시를 구체화한다. LLM 평가가 게시 전에 필수인지 여부는 OPEN-008의 미결정 사항이다. 이는 제품 구현 단위나 개발 일정의 확정이 아니다.

## 투자·시각안·인력

시장 조사·목업·팀 편성은 이번 승인된 작업 계획에서 제외되었으며 관련 검증·확보 결과는 없다. 별도 사람 승인권자는 없다. 예산 상한·마감·조직상 차단 요인은 정해지지 않았고 유료 서비스는 비용 조건을 먼저 결정한다. 이 문서는 비용 집행·인력 채용의 승인이 아니다. 근거: [전달 확인 답변](approval-handoff-questions.md).

## 진행 권고와 남은 결정

추가 진행 조건 없이 상세 요구사항·설계를 진행하는 것을 권고한다. [단계 경계 점검](../../verification/phase-check-ideation.md)은 문서 간 목적·범위·백로그 연결을 확인하며 실제 연동 검증을 대체하지 않는다. OPEN-001~020의 남은 정책·데이터 형식·승인 신뢰성·제공자·공유·보존·충돌 처리 조건은 후속 요구사항·계약·기능·비기능 설계에서 확정한다. 판단 근거와 미결정 항목을 기존 요구사항 ID에 연결한다.
