# Garmin Training Agent 목적 정의

## Problem Statement

개인 Garmin 사용자의 운동 기록 수집·분석·훈련 계획·일정 관리를 연결하여 수작업을 줄인다. [Q1]

## Target Customer

개인 Garmin 사용자가 대상이다. 기록 정확성, 계획에 대한 사용자 통제, 개인정보 보호, 연동 상태 확인을 핵심 가치로 삼는다. [Q1] [Q4]

## Success Metrics

| 기준 | 확인할 결과 | 근거 |
|---|---|---|
| 제품 전체 흐름 | 수집→분석→명시적 계획 승인→저장→일정 게시가 연결됨 | [Q2] |
| 장애 시 보존 | 외부 연동 장애에도 기존 기록과 승인 계획이 보존됨 | [Q2] |
| 설계 추적성 | 요구사항 ID와 설계의 연결, 미결정 사항, 검증 조건을 명시함 | [Q2] |
| 검증의 구분 | 실제 연동 성공은 별도 검증하며 설계만으로 성공을 주장하지 않음 | [Q2] |

## Initiative Trigger

요구사항 v1.1을 개인 훈련 지원 제품의 설계로 구체화하기 위해 착수한다. [Q3]

## Initial Scope Signal

- workflow-selected: `classic`. [scope]
- 이번 요청은 제공 요구사항 문서를 바탕으로 설계를 시작하는 것이다. [desc]
- 초기 제품은 P0를 대상으로 하고 P1/P2는 후속 범위로 구분한다. [Q7]
- 상용 다중 사용자·과금·모바일 앱은 제외한다. Garmin 시계 직접 게시는 권한 검증 전 제외한다. [Q7]
- 로컬 직접 호출·상시 클라우드·별도 Garmin MCP 서버는 필수로 두지 않는다. 외부 쓰기 지원은 실제 검증을 조건으로 한다. [Q7]
- 범위와 우선순위는 요청자가 최종 결정한다. [Q5]
