# 타당성 평가

## 근거와 판정 범위

- [승인된 목적 정의](../intent-capture/intent-statement.md): 개인용, P0 우선, 명시적 승인, 장애 시 보존 및 실제 연동 검증의 구분.
- [확인된 답변](feasibility-questions.md): Q1~Q7 및 요약 확인.
- [요구사항 v1.1](../../../../../../../docs/GARMIN_TRAINING_AGENT_REQUIREMENTS.md): DEC, VAL, OPEN, AT 식별자는 후속 설계·검증의 기준이다.

## 종합 판단

**설계 진행은 조건부로 가능하다.** 이는 설계상 판단이며 제품의 실제 실행 가능성이나 외부 연동 성공을 확인한 판정이 아니다. 현재 확인된 사용자 환경과 요구사항을 기준으로 설계를 진행하되, Garmin 데이터 접근, ChatGPT 자료 읽기·Drive 쓰기, Calendar 게시의 실제 권한과 동작을 구현 전 검증 조건으로 유지한다. 외부 기능이 지원되지 않는 경우의 대체 경로와 사용자 고지를 설계해야 한다.

## 확인된 제약

Rust 및 Ubuntu 24.04 이상을 대상으로 하며 로그아웃 중 자동 실행이 필요하다. 사용자에게 Rust 경험은 없고 추가 필수 기술은 없다(Q3·Q7). 필수 AWS 서비스는 없으며 Linux 개인 PC 중심이다(Q6). 예산 상한·마감·조직상 차단 요인은 정해지지 않았고, 유료 서비스는 비용 조건을 정한 뒤 검토한다(Q5).

## 주요 위험과 대응

외부 연결 환경의 미지원 기능을 확정하면 핵심 흐름을 구현할 수 없을 수 있다. 따라서 실제 가능 여부를 먼저 확인하고 지원 불가와 대체 절차를 명시한다. 승인·저장·수신·게시를 혼동하면 미승인 일정 또는 중복 일정이 발생할 수 있으므로 별도 상태와 검증 기준을 후속 계약·기능 설계에서 정한다. 상세 항목과 해소 조건은 [RAID 기록](raid-log.md)에 둔다.

## 후속 설계 진입 조건

범위 정의 단계에서는 P0와 후속 범위를 유지하면서 미검증 의존성을 조건으로 명시한다. 문서 설계는 계속할 수 있지만 미검증 경로를 지원 확정으로 표현하지 않는다. OPEN-001~020의 상세 정책은 관련 요구사항·계약·기능·비기능 설계에서 결정한다. 이번 단계에서 API 호출·실제 데이터 수집·외부 쓰기·로그아웃 시험은 수행하지 않았다.
