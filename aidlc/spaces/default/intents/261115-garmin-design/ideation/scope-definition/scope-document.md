# 초기 제품 및 설계 범위

## 근거

[목적 정의](../intent-capture/intent-statement.md), [타당성 평가](../feasibility/feasibility-assessment.md), [제약 목록](../feasibility/constraint-register.md), [이번 단계 답변](scope-definition-questions.md), [요구사항 v1.1](../../../../../../../docs/GARMIN_TRAINING_AGENT_REQUIREMENTS.md)을 기준으로 한다.

## 이번 작업의 결과

요구사항에 추적 가능한 제품 설계를 작성한다. 구현·실제 배포는 이번 작업에 포함하지 않는다. 문서 완성과 실제 서비스 연동 성공을 구분하며, 외부 검증 전에는 지원 가능성을 확정하지 않는다.

## 초기 필수 범위

문서의 모든 P0 요구사항을 초기 필수로 유지한다. 다음 표는 기능 묶음이며 상세 요구사항을 삭제하거나 대체하지 않는다.

|---|---|---|
| 설치·운영 | Rust·Ubuntu 24.04 이상, CLI 설정·제거·주기 변경·즉시 실행·오류 안내, 로그아웃 중 자동 실행 | INS-001~008, 타당성 Q7 |
| 수집 | 인증·운동 목록/상세·신규/수정 동기화·종목/단위/출처 구분·누락/오류 처리 | GAR-001~007, GAR-010~011 |
| 저장 | 로컬 우선 보존, GitHub·Drive 선택 또는 병행, 대상별 독립 상태·충돌·중복 방지·비공개 | STO-001~009 |
| 분석 자료 | 기간별 요약·구조화 자료·최신성·누락과 0 구분·종목별 통계·민감정보 제한 | DAT-001~009, DAT-012 |

## 종목 및 설치 경계

초기 훈련 계획은 러닝을 우선 지원한다(Q1). 수영 등 다른 종목의 수집·구분·기간 통계는 GAR-006과 DAT-007에 따라 유지하며, 러닝 계획에서 사용자가 등록한 수영 등의 고정 운동과 회복·휴식을 고려하는 PLN-003도 유지한다. 수영·사이클 전용 계획과 다종목 통합 분석은 후속이다.

사용자 한 명·한 대 PC에서 자동 동기화·게시를 수행한다(Q2). 다중 PC 동시 실행 지원은 후속이다. 이 제한은 한 PC 내 중복 실행 방지나 ChatGPT·Drive 클라이언트의 동시 수정 충돌 탐지를 제외하지 않는다(INS-006, CMD-007).

## 후속 및 제외 범위

P1/P2는 후속 백로그로 보존하며 초기 완료 조건에 임의로 편입하지 않는다. 생활 일정 자동 충돌 분석·재배치, 장기 코칭 이력, 다종목 통합 분석, 피드백, 시나리오 비교, 정량 예측, 추가 전달 대상, 확장 평가 기능이 포함된다. 설명·변경 이력·사용자 통제 중 이미 P0인 부분은 유지한다.

상용 다중 사용자·과금·별도 모바일 앱은 제외한다. Garmin 시계 직접 게시는 공식 권한 검증 전 제외한다. 상시 클라우드·별도 Garmin MCP 서버·ChatGPT의 Linux 직접 호출을 필수로 두지 않는다. AWS·Bedrock은 전제하지 않는다.

## 우선순위 및 의존성

위험 우선(Q3)으로 Garmin 접근, ChatGPT 읽기·저장 가능 여부, 승인 신뢰성을 먼저 검토한다. 이후 수집·보존→분석 자료→목표·계획 승인→Drive 수신·검증→평가·일정 게시를 구체화한다. LLM 평가와 게시의 정확한 선후 및 실패 정책은 OPEN-008의 후속 결정이며 이 흐름으로 확정하지 않는다.

## 가치 흐름

사용자 설정 → 운동 기록 수집·보존 → 분석 가능한 자료 전달 → 목표와 러닝 계획 검토 → 명시적 승인 → 저장·수신 확인 → 승인된 일정 게시 → 상태·오류 확인 및 복구.

사용자는 기록에서 계획으로, 계획에서 일정으로 이어지는 흐름과 각 단계 상태를 확인한다. 승인·저장·수신·게시 성공은 서로 다른 결과다.

## 완료 기준과 변경 통제

초기 제품 완료는 모든 적용 P0 및 관련 인수 시나리오 검증을 요구한다. 문서 설계 완료만으로 이를 충족했다고 판단하지 않는다. 현재 외부 연동과 로그아웃 실행은 미검증이다. 고정 마감은 없다.

외부 기능이 P0를 충족하지 못하면 문서가 허용한 수동 저장 등 대안을 평가한다(Q4). 대안도 충족하지 못하면 해당 경로를 보류하고 요청자가 범위 변경을 결정한다. 자동 저장처럼 표시하거나 완료 기준을 임의 축소하지 않는다. 미결정 OPEN 항목은 요구사항·계약·기능·비기능 설계에서 결정하고 결과를 요구사항 ID에 연결한다.
